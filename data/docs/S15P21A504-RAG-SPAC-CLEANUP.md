# RAG 담당께 — 스팩 기업 31,020행을 지워도 될까요? (2026-09-22)

한 줄 요약: **껍데기 회사 41곳을 서비스에서 빼기로 했는데, 마지막 한 걸음이
`rag_evidence` 에 막혀 있습니다.** 지워도 되는지만 확인 부탁드립니다.

- 물어보는 사람: 데이터 담당 (박세은)
- 관련 MR: !262 (머지됨)

---

## 1. 스팩이 뭔가요

**기업인수목적회사(SPAC)** 입니다. 증권사가 "나중에 괜찮은 회사를 찾아 합치겠다"는
목적만 가지고 먼저 상장시켜 두는 **빈 회사**입니다. 이름이 전부 이런 식입니다.

```
교보15호스팩 · 신한제12호스팩 · KB제29호스팩 · SK증권제11호스팩 …  (41곳)
```

사업이 없습니다. 운영 DB 실측입니다.

| | |
|---|---|
| 매출 | **0원** (41곳 전부) |
| 직원 | **1~2명** (임원뿐) |
| 시설투자 | 0건 |
| 자본 75억~122억 | 공모로 모아 **신탁에 넣어 둔 돈** |

취업 준비생이 보는 서비스인데 **직원 2명짜리 껍데기에는 지원할 수가 없습니다.**

---

## 2. 왜 빼기로 했나

QA 에서 "검색에 스팩이 쏟아진다"는 지적을 받았는데, 열어 보니 더 큰 문제가
있었습니다.

```
'금융 및 보험관련 서비스업'(66199) 평균 직원수
  스팩 포함:    81명
  스팩 제외: 1,198명      ← 15배 차이
```

이 업종 28곳 중 **27곳이 스팩**이라, 그 업종 실제 회사의 "업종 평균 대비" 비교가
화면에서 무의미한 숫자로 나가고 있었습니다.

MR !262 로 수집 모집단에서 빼기로 했고 머지됐습니다.

---

## 3. 지금 막힌 곳

`company` 테이블에서 스팩 41곳을 지워야 검색에서 사라지는데, **`rag_evidence` 가
그 회사들을 참조하고 있어 지울 수가 없습니다** (FK).

```
company (스팩 41곳)  ←  rag_evidence 31,020행
                          └ rag_evidence_embedding
                          └ rag_evidence_entity_scope
```

`company` 를 참조하는 표가 13개인데 **나머지 12개는 전부 0건**입니다. 여기만
남았습니다.

| | 규모 |
|---|---|
| 지워야 하는 `rag_evidence` | **31,020행** |
| 전체 `rag_evidence` | 10,193,372행 |
| 비중 | **0.3%** |

임베딩이 1:1 로 붙어 있어 같이 지워집니다.

## 4. 여쭙는 것

**이 31,020행을 지워도 될까요?**

제 생각에는 지우는 게 맞습니다 — 스팩 사업보고서 내용이라 검색·분석에 쓸 일이
없고, 남겨 두면 RAG 가 껍데기 회사 문서를 후보로 들고 있게 됩니다.

### 여쭙는 진짜 이유 — 되돌리기가 비대칭입니다

지우는 건 쿼리 한 줄인데, **되돌리는 쪽이 스크립트를 벗어납니다.**

`export_rag_data.py --corp-code` 로 **뽑는 것**은 41곳만 됩니다. 그런데
`load_rag_data.sh` 가 **빈 표에만 적재**합니다.

```bash
# load_rag_data.sh:51-52
n=$(psql_t -tAc "select count(*) from $t")
[ "$n" = 0 ] || { echo "  $t 에 이미 $n 건이 있습니다. 비우고 다시 하세요." >&2; exit 1; }
```

그래서 41곳만 되돌리려 해도 스크립트는 "이미 1,019만 건 있다"며 거부합니다.
전체 TRUNCATE 후 재적재하거나, psql 로 직접 COPY 하는 수작업이 됩니다.

**데이터를 잃는 건 아닙니다** — 원본 DB 에 그대로 있습니다. 다만 되돌릴 일이
생기면 원본을 들고 계신 담당자 손이 필요합니다. 그래서 미리 여쭙습니다.

지금 임베딩 float16 전환 중이신 걸로 알아서, 타이밍이 괜찮은지도 함께 봐 주시면
좋겠습니다.

### 답만 주시면 저희가 합니다

| 답 | 저희가 할 일 |
|---|---|
| **지워도 된다** | dev → 운영 순으로 지우고 `company` 41곳까지 정리 |
| **나중에 하자** | 그때까지 검색에 스팩 이름이 남습니다 (숫자는 이미 정상) |
| **남겨야 한다** | 이유를 알려주시면 다른 방법을 찾겠습니다 (화면에서 거르기 등) |

## 5. 참고 — 급하지는 않습니다

숫자 왜곡은 **이미 고쳤습니다.** 2026-09-22 에 dev 에서 `company_metric` 의 스팩
502행과 뉴스 22행을 지워, 업종 평균이 1,198명으로 정상화됐습니다.

지금 남은 것은 **검색 목록에 이름이 보이는 것**뿐입니다. 내일 QA 전까지 정리되면
좋겠지만, 확인이 먼저입니다.

지울 때 쓸 쿼리는 이것입니다 (참고용, 실행은 확인 후에).

```sql
WITH spac AS (SELECT corp_code FROM company WHERE corp_name LIKE '%스팩%')
DELETE FROM rag_evidence WHERE corp_code IN (SELECT corp_code FROM spac);
```

**자식 표는 손대지 않아도 됩니다.** FK 삭제 규칙을 확인했더니
`rag_evidence_embedding` 과 `rag_evidence_entity_scope` 가 둘 다 **CASCADE** 라,
`rag_evidence` 를 지우면 같이 지워집니다 (2026-09-22 dev 실측).

반대로 `company` 를 참조하는 13개 표는 `cover_letter`(SET NULL) 하나만 빼고 전부
**NO ACTION** 입니다 — 그래서 `rag_evidence` 가 남아 있으면 `company` 삭제가
막히는 것이고, 이 문서를 쓰게 된 이유입니다.

**남은 것은 적용뿐이다.** DB 접속이 가능해지면 아래 한 줄로 끝난다.

```
psql -h localhost -U ssafy -d company_analysis -f sql/ddl.sql
```

작성하며 판단한 것

- **`verdict` 에 CHECK 를 걸지 않았다.** DESIGN 5장은 4종(verified/unverified/
  rejected/not_found)인데 프로토타입은 지표마다 다른 값을 낸다(매출 `conflict`·
  `single_source`, R&D `high`·`no_section`). 지금 CHECK 를 걸면 적재가 막힌다.
  **WP-6에서 매핑을 확정한 뒤 `ALTER` 로 추가한다.**
- 인덱스 7개: `ksic_division` / `stock_code` / 이름 2컬럼 pg_trgm GIN /
  `(bsns_year, revenue DESC)` 부분 인덱스(비교 목록 정렬) / `verdict` /
  `(metric_code, bsns_year)`
- 금액은 `BIGINT`(원). 매출 333.6조 = 3.3e14 로 여유 있다

```
company          PK corp_code                            기업 마스터 + KSIC
company_year     PK (corp_code, bsns_year)               지표 값 (wide)
metric_evidence  PK (corp_code, bsns_year, metric_code)  근거·판정
```

- `corp_name`(DART 등록명) / `display_name`(표시용) **분리 필수** — 엔씨소프트 DART 등록명은 `(주)엔씨`
- 검색 인덱스는 두 이름 컬럼 모두. 부분일치 검색이면 `pg_trgm` GIN 검토
- `company.listed_from` — 상장 이전 결측을 "수집 실패"와 구분

### WP-5 · 수집 파이프라인 — 3h  ✔ **완료 (2026-08-28)**

산출물: `pipeline/collect.py` · `pipeline/targets.py` · `scripts/collect.py` · `_log/ingest_log.csv`

실측: 기업-연도 50건 중 47건 수집 / 3건 `pre_listing`, 로그 238행, **실패 0**.
실제 호출 34건(2.7MB) / 캐시 201건.

작성하며 판단한 것

- **CFS·OFS 를 둘 다 받는다.** 프로토타입은 CFS 에서 매출을 못 찾으면 OFS 로
  폴백하는데 그 판단은 값을 봐야 가능하다 = 해석이다. 수집 계층은 둘 다 받아두고
  선택은 정규화에 맡긴다. 비용은 기업-연도당 1콜.
- **상장 이전 연도는 호출조차 하지 않는다.** `listed_from` 기준으로 `pre_listing`
  으로 기록한다. 실패와 섞이면 커버리지가 왜곡된다.
- **로그는 행 단위로 즉시 기록한다.** 처음엔 실행 끝에 한 번에 썼는데, 그러면
  중단 시 무엇을 받았는지가 통째로 사라져 재처리를 할 수 없다.
- `--retry` 는 기업-연도 단위로 재실행한다. 성공분은 캐시로 해결되므로 실제
  호출은 실패분에만 발생한다.

| 항목 | 내용 |
|---|---|
| 선행 | WP-2, D-1 |
| 산출물 | 수집 모듈 + `data/_log/ingest_log.csv` + 실패 목록 |
| 닫는 AC | **F-06** AC3 "누락 항목이 수집 로그에 남는다" / **F-12** AC3 "수집 실패는 재처리 가능하게 기록된다" |
| 완료 판정 | 65건 수집 로그가 남고, 실패 목록을 입력으로 재실행 가능 |

**핵심: 수집과 정규화를 분리한다.** 수집 계층은 API 호출과 raw 저장만 하고 해석하지 않는다. 이 구조가 없으면 파싱 규칙을 고칠 때마다 API를 다시 타야 한다 — 이번에 R&D 파서를 5번 고쳤다.

`data/raw/`에 4,201파일이 이미 있으므로 개발 중에는 호출이 거의 발생하지 않는다.

```sql
INSERT INTO company_year (...) VALUES (...)

```

수집 멱등성은 raw 캐시로 이미 있다. 적재 멱등성을 추가하면 **파이프라인 전체가 안전하게 재실행된다.**

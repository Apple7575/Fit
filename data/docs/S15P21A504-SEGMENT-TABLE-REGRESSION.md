# 부문별 매출이 24% 사라집니다 — 표 행 병합 회귀 (2026-09-21)

**지금 develop 코드로 사업보고서를 다시 파싱하면 부문별 매출 6,391행(24%)이 사라집니다.**
문서 1,172건은 부문 매출이 통째로 없어집니다. 기아·HD현대가 포함됩니다.

**아직 아무 데이터도 망가지지 않았습니다.** develop 의 시드 CSV 는 9/19 산출
그대로(부문매출 47,816행)이고 dev DB 도 같습니다. 다음에 **누군가 시드를 다시 만들어
올리는 순간** 반영됩니다 — 그리고 적재가 자동이라(MR !176·!196·!197) dev DB 까지
조용히 따라갑니다.

파서를 되돌리자는 얘기가 아닙니다. `doc.py` 변경은 의도가 있는 수정이고, 그 의도를
아는 쪽이 고치는 게 맞다고 봅니다. **무엇이 어떻게 깨지는지만 정확히 넘깁니다.**

## 한 문서로 재현됩니다 — 기아 2022 (`20230309000734`)

같은 문서, 같은 표(68번)를 두 코드로 읽은 결과입니다.

| | 행 | 제품 | 기타 | 제품 외 기타 |
|---|---:|---:|---:|---:|
| `db33f2c` (수정 전) | **3** | 79,706,978 | 7,157 | 6,549,075 |
| `cffc82f` (현재 develop) | **2** | **79,714,135** | — | **13,098,150** |

단위는 양쪽 다 백만원(`직전표-1`)으로 같게 잡습니다. 값만 보면 무슨 일이 났는지
바로 보입니다.

```
79,714,135 = 79,706,978 + 7,157      ← '기타' 행이 '제품' 에 흡수됐다
13,098,150 = 6,549,075 × 2           ← '제품 외 기타' 가 두 번 더해졌다
```

**행이 병합되면서 값이 옆 행으로 옮겨 붙고 일부는 중복 계산됩니다.**

## 그 결과 표 선택이 뒤집힙니다

`segments.extract()` 는 후보 표를 앞에서부터 보며 **합계 대조를 통과한 첫 표**를
채택하고, 통과하는 표가 없으면 **부문 수가 가장 많은 표**를 돌려줍니다.

| | 표 68 합계 | DART 매출 대비 | 채택 |
|---|---:|---:|---|
| 수정 전 | 86.26조 | **0.34%** → `verified` | 표 68 ✅ |
| 현재 | 92.81조 | **7.22%** → `mismatch` | 표 68 탈락 |

표 68 이 탈락하자 부문 수가 더 많은(3개) **표 65** 가 대신 채택됩니다. 그런데 표 65 는
부문별 매출표가 아니라 **내부거래 상계표**입니다.

```
총매출액    46,409,721
내부매출액 -21,874,391      ← 음수. 부문 매출일 수 없다
순매출액    24,535,330
합계 49.07조 vs DART 86.56조 → 오차 43.31% → mismatch → 행을 통째로 버린다
```

후보 표 목록은 양쪽이 `[65, 28, 30, 66, 68, 69]` 로 **완전히 같습니다.** 후보를 고르는
단계가 아니라, 표 안의 행이 병합돼 합계가 틀어진 것이 원인입니다.

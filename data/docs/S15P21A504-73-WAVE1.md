## 1. 실행

```
유니버스   select_business_report_universe.py --companies 300
수집       collect_business_reports.py            958건 · 0.42GB 수신 · 실패 0
업로드     개발 PC → EC2 tar 스트림                73초
HDFS       hdfs_put_business_reports.py           1,445건 6.56GB · 82초
파싱       spark_parse_business_reports.py        16파티션 · 34분 27초
```

`--companies` 인자를 선정 스크립트에 새로 뒀다. 100개사가 상수로 박혀 있어 차수를
늘릴 수 없었다. **앞 N개사는 집합으로 고정된다** — 매출 순위가 고정이라 뒤에 붙기만
한다. 다만 파일 안의 줄 순서는 달라질 수 있는데, `existing_seed` 판정이 현재 시드를
보기 때문이다(100개사를 파싱해 시드가 늘면서 13 → 85개사가 됐다). 순서에 기대는
코드는 없다.

## 2. 판정 분포 — 신규 200개사에서 무엇이 달라지나

| 지표 | 판정 | 기존 100 | 신규 200 |
|---|---|---:|---:|
| 부문 매출 | verified | 61.2% | **58.4%** |
| | mismatch | 32.9% | 34.8% |
| 시설투자 | ok | 58.7% | **32.3%** |
| | no_table | 40.9% | **64.8%** |
| R&D | high | 63.9% | **56.4%** |
| | no_section | 6.0% | **11.4%** |
| | no_row | 3.9% | **11.1%** |

**`mismatch` 비율이 거의 그대로인 것이 중요하다.** 뽑아낸 숫자의 정확도는 유지되고,
늘어난 것은 "찾지 못했다"(`no_table`·`no_section`·`no_row`) 쪽이다.

다만 **"못 찾은 것"과 "원문에 없는 것"은 아직 구분하지 못한다.** 신규 200개사는
매출 순위가 낮아 중소형·비제조가 섞이는데, 이들은 시설투자·연구개발을 애초에
공시하지 않는 경우가 많다. 2차에서 업종별로 뭉쳐 있는지 보면 갈린다.

## 3. 잡은 것 — 시설투자 금액이 1억 배로 읽혔다

F축이 34건 실패로 잡아냈다. 거의 전부 한 회사(SJG세종)였고 값이 **240조원**이었다.

### 원인은 남의 표에 붙은 단위다

```
[51] (단위 : 억원)              ← 국내 표(52번)용
[52] 국내 설비투자 표
[53] (단위 : 불, 위엔, 유로)     ← 해외 표(54번)용
[54] 해외 종속회사 설비투자 표    ★ 문제의 표
```

파서는 표 바로 앞부터 3개까지 거슬러 오르며 단위를 찾는다. 53번의 `불·위엔·유로`는
단위 목록에 없어 **그냥 지나치고 51번의 `억원`을 집었다.** 원본 `2,405,900`(위안)에
1억을 곱해 240조원이 됐다.

같은 회사 2024년에는 더 고약한 모양이 있었다.

```
[57] (단위 : 불, 위안, 유로, 원)   ← 한 표에 통화가 섞여 있다
```

여기서 `원`을 집으면 4,123,010원 같은 **그럴듯한 값**이 나와 자릿수 검증도 통과한다.
240조원은 눈에 띄지만 이건 안 띈다 — **조용히 틀리는 쪽이 더 위험하다.**

### 고친 규칙

`patterns.yaml` 에 `foreign_currency_markers` 를 두고, 거슬러 오르다 외화 단위표를
만나면 **거기서 멈춘다.** 원화가 같이 적혀 있어도 외화가 이긴다 — 행마다 통화가
다른 표는 곱할 수를 하나로 정할 수 없고, 환산율도 없다. 버린 표는 `unit_unknown`
으로 세어져 통계에 남는다.

### 값은 이렇게 움직였다

| | 고치기 전 | 고친 뒤 |
|---|---:|---:|
| F축 실패 | 34건 | **10건** |
| 시설투자 행 | 2,282 | 2,191 (−91) |
| 시설투자 기업 | 138 | 135 |

빠진 91행 중 **77행이 신규 200개사**(해외 종속회사 투자표)이고, **14행이
두산에너빌리티**다. 뒤엣것은 공짜가 아니다 — 그 표의 단위 표기가
`(단위: 백만원 / 밥캣은 천USD)` 라, **맞게 읽히던 백만원 행까지 함께 빠졌다.**
행마다 통화를 갈라 읽으려면 `A은/는 B` 형태의 문장을 해석해야 해서 지금은 버린다.
**조용히 틀린 값을 넣는 것보다 없는 편이 낫다**는 판단이다.

## 4. 남은 실패 11건

### F축 10건 — 이번엔 값이 너무 작다

```
이지홀딩스 2022  unit=원     1원 · 2원
강원랜드   2021  unit=원   199원 (하이원 루지) · 288원 (탄광문화공원)
비에이치   2021  unit=천원  23,000원 (자산형태)
```

단위를 못 찾아 `원`으로 읽었거나 열이 밀려 엉뚱한 칸을 집은 것으로 보인다.
**자릿수를 크게 틀리는 쪽은 닫혔고 작게 틀리는 쪽이 남았다.** 위험도가 낮아 2차에서
표본을 모아 한 번에 보는 편이 낫다고 판단했다.

### D축 1건 — 경계값

`에코프로 2022` 부문합 5.36조 vs 매출 5.64조, **오차 5.0%** 로 허용치에 딱 걸렸다.
856/857 은 통과했고 지주사 내부거래 제거로 보인다. 1건이라 패턴 문제로 보지 않는다.

## 6. 2차 전에 볼 것

1. **"한 표에 단위 둘" 이 얼마나 되나** — 두산에너빌리티처럼 맞던 행까지 버리는
   경우가 많으면 행별 통화 해석을 만드는 것이 맞고, 적으면 지금처럼 버리는 것이 맞다
2. **`no_table`·`no_section` 이 업종별로 뭉쳐 있나** — 뭉쳐 있으면 그 업종의 표 제목이
   다른 것이므로 `patterns.yaml` 을 늘린다. 흩어져 있으면 원문에 정말 없는 것이다
3. F축 남은 10건의 표를 함께 본다 (1번과 같은 자리에서 보인다)

**임계값을 풀지 않는다.** 커버리지가 아쉬우면 패턴을 늘린다 (F-27 AC1 · 팀장 기준 4항).

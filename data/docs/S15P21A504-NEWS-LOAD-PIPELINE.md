# 뉴스 적재 경로 설계 (2026-09-21)

전 종목 확대가 확정되면서(9/21 팀장) **지금의 수작업 경로로는 감당이 안 된다.**
무엇이 막히는지와, 주 1회 무인으로 도는 경로를 적는다.

- 작성: 데이터 담당 (박세은)
- 확정된 범위: 전 종목 2,703개사 · 기업당 최신 5건 · 주 1회 · AI 점수 미채택

## 1. 지금은 왜 안 되나

시드 CSV 를 저장소에 커밋하지 않기로 했다(구글 뉴스 RSS 의 저장·재배포 근거를
확보하지 못했다 — `news-poc/90-source-review.md`). 그래서 **Jenkins 가 보내는 꾸러미에
뉴스 파일이 없다.**

```
Jenkinsfile Load-Seed → tar czf - data/curated/seed ... → 서버 → ci_load_seed.sh
                              └ news_article.csv 는 .gitignore 라 여기 없다
load_seed_csv.py → "news_article 시드가 없거나 비어 있다 — 건너뜀"
```

그래서 뉴스만 사람이 넣고 있다. 지금은 500행이라 견디지만 **13,500행이 되고 주기가
생기면 매주 사람이 붙어야 한다.** 게다가 수집기는 노트북에만 있고(저장소 밖) 3.8시간이
걸려 그동안 노트북이 깨어 있어야 한다.

## 2. 설계 — 수집부터 적재까지 서버에서 주 1회

**저장소에는 코드와 계보만, 데이터는 서버와 DB 에만 둔다.** 커밋 금지 결정은 그대로다.

```
[Jenkins: news-weekly, 일요일 03:00 KST]
  └ 저장소 체크아웃 → 1호기(j15a504)에서 아래를 순서대로
      ① collect_news.py      2,703개사 × 주 단위 창 1쿼리 (5초 간격, 약 3.8시간)
                             → /home/ubuntu/newsdata/raw/<run-id>/*.xml
      ② import_news_raw.py   원본을 계보와 함께 들인다 (--target-start/--target-end)
      ③ stage_news.py        staged/articles.csv
      ④ build_news_seed.py --per-company 5
                             → curated/seed/news_article.csv + manifest
      ⑤ load_seed_csv.py --only news_article
                             dev 는 자동 · prod 는 파라미터를 켠 실행에서만
```

**작업 디렉터리는 `/home/ubuntu/newsdata` 다.** `dataload` 와 분리한다 — 그쪽은 CD 가
매 배포마다 통째로 갈아엎는다. 적재는 기존 `ci_load_seed.sh` 와 **같은 락
(`flock /tmp/ca-seedload.lock`)** 을 잡아 시드 적재와 겹치지 않게 한다.

### 왜 서버인가

노트북은 3.8시간 동안 깨어 있어야 하고 절전되면 끊긴다. 서버는 상시 가동이고 도커·DB 가
이미 있다. 수집은 CPU 를 거의 쓰지 않고 대부분 5초 간격 대기라 다른 작업에 영향이 적다.

### 왜 주 단위 창인가

수집기가 **기업 하나씩 · 요청 간격 5초 하한**이라 쿼리 수가 곧 시간이다.

| 방식 | 요청 | 시간 |
|---|---:|---:|
| 지금처럼 `기업 × 하루` 창으로 일주일치 | 18,921 | 26시간 (불가) |
| **주 단위 창 1쿼리** | 2,703 | **3.8시간** |

기업당 5건만 남기므로 응답 100건 상한에 걸려도 손해가 아니다. 지금도 일 단위에서 15%가
상한에 닿는다.

## 3. 안전장치

- **행수 급감 가드가 이미 있다** (MR !210). `build_news_seed.py` 가 직전 주 계보와
  대조해 5% 넘게 줄면 **시드를 쓰지 않고 멈춘다.** 수집이 절반만 돼도 DB 까지 가지 않는다
- **수집 실패율**이 5%를 넘으면 시드 생성으로 넘어가지 않는다 (`failed_*.csv` 로 남기고
  다음 실행에서 재시도)
- **운영은 사람이 켤 때만** — 기존 Load-Seed 의 `LOAD_SEED_PROD` 와 같은 규칙으로
  `LOAD_NEWS_PROD` 를 둔다
- 가드나 실패율에 걸리면 빌드를 UNSTABLE 로 두고 적재를 건너뛴다

## 4. 무엇이 어디에 남나

| 것 | 어디 | 왜 |
|---|---|---|
| 수집기·적재 코드 | **저장소** | 코드는 커밋 금지 대상이 아니다. 지금은 노트북에만 있어 남이 못 돌린다 |
| 원본 XML | 서버 `newsdata/raw/` **4주 롤링** | 주당 약 120MB. 4주면 480MB 다 |
| 시드 CSV | 서버 + DB | 커밋 금지 그대로 |
| 계보(manifest) | 서버 + Jenkins 아티팩트 | **자동 커밋은 하지 않는다** — 봇이 보호 브랜치에 쓰는 구조를 만들지 않는다 |

**정본은 DB 다.** 저장소에서 복구할 수 없으므로, 잃으면 재수집한다. 다만 구글이 과거
구간을 얼마나 돌려주는지는 보장이 없어 **복구 가능성은 실측이 필요하다** (첫 실행 때
지난주 창을 한 번 받아 본다).

## 5-1. ⚠️ MR !209(V34)가 먼저 들어오면 이 경로가 멈춘다 — 실측

`fix/S15P21A504-news-article-erd-columns` 의 V34 가 `source`·`guid` 를 지우고
`publisher`·`provider`·`provider_article_id`·`provider_url`·`normalized_url`·
`body_text` 를 더한다. **그 파일을 우리 마이그레이션 폴더에 넣고 파서를 돌려 봤다.**

```
V34 적용 뒤 키로 읽히는 칸: corp_code(UK) · provider(UK) · normalized_url(UK)
                            · provider_article_id(UK)
load_seed_csv._check_keys → "자연키가 스키마와 다르다 —
    코드 ('corp_code','guid') vs Flyway ('corp_code','provider',
    'normalized_url','provider_article_id')"
```

**적재가 통째로 멈춘다.** 세 가지를 같이 고쳐야 한다.

| 무엇 | 왜 |
|---|---|
| `load_seed_csv.NATURAL_KEYS` | `guid` 가 없어진다 |
| `_check_keys` | 부분 UNIQUE 인덱스 **둘**을 한 자연키로 합쳐 읽는다. 지금 구조로는 "서로 다른 유일키 두 개"를 표현할 수 없다 |
| `pipeline/news/schema.SEED_FIELDS` | 헤더 상수에 `source`·`guid` 가 박혀 있다 |

덧붙여 두 가지를 봐 주셨으면 한다.

- **`normalized_url` 은 채울 수가 없다.** 우리가 가진 링크는 전부 구글 뉴스 링크이고,
  원문 주소로 푸는 세 방법이 2026-09-21 실측에서 모두 실패했다(오프라인 해독 500/500
  실패 · 리다이렉트 추적은 본문 0바이트 · 구글 내부 API 는 서명이 필요). 그래서
  `normalized_url` 기준 부분 UNIQUE 인덱스는 **당분간 한 행에도 걸리지 않는다**
- **`body_text` 는 기사 본문이다.** 저장·재배포 근거를 확보하지 못해 시드조차 커밋하지
  않기로 한 결정(`news-poc/90-source-review.md`)과 정면으로 부딪힌다. 컬럼을 만드는
  것과 채우는 것은 다른 문제지만, **채울 계획이라면 그 결정을 먼저 다시 여는 것이 맞다**

순서만 맞추면 된다. **V34 를 먼저 넣고 우리 쪽 셋을 같은 날 고치거나, 우리 쪽을 먼저
고쳐 두고 V34 를 넣는다.** 지금처럼 따로 가면 그 사이에 뉴스 적재가 조용히 멈춘다.

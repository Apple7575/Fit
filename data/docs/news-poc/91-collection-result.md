# 91 — 뉴스 샘플 수집·품질 검증 결과

## 현재 판정 — 2026-09-05

**91번의 샘플 수집·검증 결과를 확정했다. 기본 후보 수집은 통과했지만, 원문 URL 95% 확보 기준은 실패했다. Google RSS만으로 전수 뉴스와 완성 요약을 안정적으로 제공할 수 있다고 결론 내릴 수 없다.** 실패와 미검증 항목을 포함한 PoC 결과 정리이며, 운영 수집기 완성을 뜻하지 않는다.

수집 방식은 **회사명만 검색 → 전날 구간까지 조회 → KST 날짜 필터 → 기사 키 중복 제거 → 명확한 오류 분리**다. 사업 키워드·언론사 분할·카테고리 분류는 사용하지 않는다.

| 처리 | 건수 | 의미 |
|---|---:|---|
| RSS 두 응답 | 200 | 각각 100건으로 포화 가능성 표시 |
| KST 날짜 필터 후 | 116 | 기간 밖 84건 제외, 대상 날짜 안 기사 키 중복 0건 |
| 제목 누락 분리 | 1 | 보존하되 분석 입력에서 제외 |
| 원문 보완 입력 | 115 | 이 전체를 확보율 분모로 사용 |

| **최종 분석 후보** | **114** | 제목 기반 관련성 실험에 인계 가능 |

기존 에이전트 검토와 대조하면 최종 114건은 관련 있음 112건·관련 없음 2건이다. 사람이 확정한 정답이나 자동 분류 성능은 아니다. 부고와 타사 행사 2건은 관련성 문제이므로 자동 오류 제거로 삭제하지 않았다.

### 원문·설명 자동 확보 실험

`experiments/collection/enrich.py`로 Google 링크를 해석하고 기사 페이지의 제목·출처 호스트·공개 설명 메타데이터를 확인했다. 본문 요약이나 AI 호출은 하지 않았다. 비공식 링크 해석 프로토콜은 [참고 구현](https://github.com/SSujitX/google-news-url-decoder)을 바탕으로 하며, 변경·호출 제한에 취약하다.

| 115건 전체 기준 | 건수 | 판정 |
|---|---:|---|
| 출처 호스트·기사 제목 일치 원문 | 15 (13.04%) | 자동 확인 기준. 원문 확보 95% 기준 미달 |
| 재게시 플랫폼 기사 | 2 | 직접 원문으로 계산하지 않음 |
| 목록 페이지 | 1 | 최종 후보에서 분리 |
| 접근 오류 | 2 | 발행사 HTTP 403 1건, Google 링크 해석 HTTP 429 1건 |
| 미실행 | 95 | Google 429에서 전체 중단. 실패 기사로 단정하지 않음 |
| 설명 메타데이터 후보 | 16 (13.91%) | 원문·재게시 포함. 검증된 완성 요약이 아님 |
| 잘림 가능성 표시 | 13 / 16 | 문장 끝 기호 기반 보조 검사이며 정답 판정 아님 |

처음 20건을 순차 시도한 결과로 무작위 표본의 추정 성공률이 아니다. **429 이후 재시도·우회하지 않았다.** 별도 과거 브라우저 50건 실험과 합산하지 않는다. 설명 16건을 확인한 결과 기사 앞부분, 잘린 문장, 제목에 기자명 등이 붙은 짧은 메타데이터가 섞여 있었다. 사이트 소개 문구를 포괄적으로 판별하는 기능은 없으며, `description_status=metadata_excerpt`는 요약 품질 통과를 의미하지 않는다. 실패·미실행 필드는 null로 유지한다.

모든 실행은 회사명만 사용했고, 각각 2개 응답이 모두 100건을 반환했다.

삼성전자 9월 4일 최초 116건과 재조회 117건을 비교하면 새로 관측된 키 7개, 다시 관측되지 않은 키 6개, 제목·게시일·설명·출처 중 변경된 필드가 있는 키 23개였다. 새 키를 실제 신규 기사, 미재관측을 삭제 기사로 해석하지 않는다. 동일 날짜에 재조회한 비교이며 다음 날 정기 실행·DB 수정 반영은 검증하지 않았다.

NAVER 결과 제목에는 유괴 예방 이벤트·교육청 워크숍 등 기업 관련성이 불명확한 네이버 블로그 글도 섞였다. **삼성전자의 관련성 검토 결과를 다른 기업에 일반화할 수 없다.** 타 기업 원문·설명 전수 보완과 사람 검토 오탐률은 미검증이다.

## 현재 수집기 재실행

저장소 루트에서 실행한다. 아래 날짜는 당시 실험을 재현하는 예시이며 최신 수집 날짜는 실행자가 지정한다. 새 실행은 별도 출력 폴더를 사용한다.

```powershell
python -X utf8 -m data.news_poc.pipeline.collect --company 삼성전자 --start 2026-09-04 --end 2026-09-05 --out data/news_poc/local_raw/recheck-samsung-0904
python -m unittest discover -s data/news_poc/tests
```

기존 성공 응답은 재사용한다. 새 요청은 네트워크 접근과 소스 조건 확인이 필요하다. `pipeline/collect.py` 결과는 기본적으로 지정 출력 폴더의 `results/`에 생성된다. `pipeline/normalize.py`는 과거 XML 정규화 실험용이므로 현재 결과 위에 다시 실행하지 않는다.

날짜·키워드 분할, 브라우저 원문 접근 등 채택하지 않은 상세 실험 서술은 정리했다. 원시 XML·결과 파일은 기존 경로에 남아 있어 수집 출처와 검증 근거를 추적할 수 있다. 과거 원문 보완·브라우저 탐색 실행기는 정리했으므로 해당 실험 전체의 재실행은 현재 지원하지 않는다. 위 collect 명령은 유지한다.

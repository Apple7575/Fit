## 0. 한 줄 요약

**같은 KSIC 중분류에 속한 타깃 기업들을, 해당 연도 매출 내림차순으로 나열한다.
조회한 기업은 매출 순위와 무관하게 항상 포함한다.**

## 1. 모집단 (D-1 = A)

비교 후보는 **`config/targets.csv` 의 10개사**로 한정한다. 같은 KSIC의 상장사 전체(안 B)가 아니다.

| 근거 | |
|---|---|
| 수집 비용 | B는 KSIC 26에 494개사, 58에 281개사. 업종당 수백 콜의 추가 수집이 필요하다 |
| MVP 충분성 | 업종당 5개사면 "내 기업이 업종에서 어디쯤인가"를 보여주기에 충분하다 |
| 확장성 | B가 필요해지면 `targets.csv` 에 기업을 추가하는 방식으로 넓힌다. **규칙은 그대로 쓴다** |

현재 구성 — 업종당 5개사씩 2개 업종.

```
KSIC 26 (전자부품·컴퓨터·영상·음향·통신장비)

```

> 모집단이 `targets.csv` 이므로, **적재 시 `company` 테이블에는 상장사 3,930건이 전부 들어가지만
> 비교 대상은 지표를 수집한 기업만**이다. 둘을 구분하는 방법은 3장을 보라.

## 2. 그룹 기준

**`company.ksic_division`** (KSIC 중분류 2자리) 가 같으면 같은 그룹이다.

DART 원본 `induty_code` 는 3~5자리가 혼재하므로 그대로 쓰지 않는다. 앞 2자리를 잘라
`ksic_division` 으로 정규화한 값을 쓴다 (`config/company_universe.csv` 에 이미 적용되어 있다).

`ksic_division` 이 비어 있는 기업은 **어느 그룹에도 넣지 않는다.** 비교 화면에서 제외하고
제외 건수를 로그로 남긴다 (5장).

---

## 3. 선정 규칙

### 3.1 포함 조건

한 기업이 `(연도 Y, 기업 C)` 의 비교 목록에 들어가려면 **전부** 만족해야 한다.

```
① C 와 같은 ksic_division
② 해당 연도 Y 의 company_year 행이 존재
③ 해당 연도 Y 의 revenue 가 NOT NULL          ← 정렬 기준이므로 필수
④ Y >= company.listed_from  (listed_from 이 있는 경우)
```

**④가 필요한 이유**: 시프트업은 2024년 상장이라 2021~23 데이터가 없다. 이건 수집 실패가
아니라 애초에 존재하지 않는 값이다. 이 구분이 없으면 "커버리지 미달"로 잘못 집계된다.

### 3.2 선택 기업은 항상 포함 (F-19 AC2)

**조회한 기업 C 는 매출 순위·개수 상한과 무관하게 목록에 반드시 들어간다.**
자기 기업이 목록에 없는 비교 화면은 의미가 없다.

단 하나의 예외: **C 자신이 3.1의 ②③④를 만족하지 못하면** 비교 화면을 그리지 않고
"해당 연도 데이터 없음"을 표시한다. 기준값이 없는데 비교만 보여줄 수는 없다.

### 3.3 정렬

```
1순위   revenue DESC        해당 연도 매출 내림차순
2순위   stock_code ASC      동률일 때
```

**동률 처리 (F-19 AC3)**: 매출이 완전히 같은 경우는 실측에서 없었지만, 정렬이 실행할 때마다
바뀌면 화면이 흔들린다. **종목코드 오름차순**으로 순서를 고정한다. 종목코드는 유일하므로
정렬 결과가 항상 결정적이다.

### 3.4 최대 노출 개수

**A 안에서는 상한을 두지 않는다** — 업종당 최대 5개사이므로 전부 보여준다.

다만 규칙과 코드에는 `max_peers` 를 남겨둔다(기본값 `NULL` = 무제한). B로 확장할 때
이 값만 채우면 되고, 그때는 **선택 기업을 제외한 나머지에만** 상한을 적용한다.

```
표시 개수 = 선택 기업 1 + min(나머지 후보 수, max_peers)
```

## 4. 데이터 부족 처리 (F-19 AC3)

지표별로 결측의 의미가 다르다. **정렬 기준인 매출과, 화면에 같이 그리는 다른 지표를 구분한다.**

| 상황 | 처리 |
|---|---|
| 해당 연도 `revenue` 결측 | **목록에서 제외.** 정렬 기준이 없으면 자리를 정할 수 없다. 제외 건수 로그 |
| 해당 연도 행 자체가 없음 | 목록에서 제외 (위와 동일) |
| `listed_from` 이전 연도 | **제외하되 "미상장"으로 구분.** 수집 실패와 같이 세지 않는다 |
| 매출은 있고 다른 지표(R&D·직원 등)만 결측 | **목록에는 남기고 해당 지표만 빈 값으로 표시.** 기업을 통째로 빼지 않는다 |
| `verdict` 가 `rejected` / `not_found` | 해당 지표를 결측으로 취급 (위 줄과 동일 처리) |
| `verdict` 가 `unverified` | **D-3 결정 대기.** 현재 권장은 "적재는 하되 화면 노출 안 함". 조회 시점에 필터 |

**원칙: 기업을 목록에서 빼는 건 매출이 없을 때뿐이다.** 다른 지표의 결측 때문에 기업이
사라지면, 지표를 하나 추가할 때마다 비교 대상이 줄어드는 이상한 화면이 된다.

## 5. 로그로 남길 것

비교 목록을 만들 때마다 **왜 이 기업이 빠졌는지**를 남긴다. 화면에서 기업이 안 보일 때
데이터 문제인지 규칙 문제인지 구분할 수 있어야 한다.

```
excluded_no_revenue      해당 연도 매출 결측으로 제외한 기업 수
excluded_pre_listing     상장 이전 연도라 제외한 기업 수 (실패 아님)
excluded_no_division     ksic_division 미상으로 제외한 기업 수
peers_returned           최종 반환 개수
```

## 6. SQL

`(corp_code = :corp_code, bsns_year = :year)` 로 조회했을 때의 비교 목록.

```sql
WITH me AS (
    SELECT c.corp_code, c.ksic_division
    FROM   company c
    WHERE  c.corp_code = :corp_code
)
SELECT c.corp_code,
       c.display_name,
       c.stock_code,
       cy.revenue,
       cy.operating_profit,
       cy.employee_count,
       cy.avg_salary_krw,
       cy.avg_tenure_years,
       cy.rnd_cost_krw,
       cy.rnd_ratio_pct,
       (c.corp_code = :corp_code) AS is_selected
FROM   company c
JOIN   company_year cy
       ON  cy.corp_code = c.corp_code
       AND cy.bsns_year = :year
JOIN   me
       ON  c.ksic_division = me.ksic_division
WHERE  cy.revenue IS NOT NULL                            -- 3.1 ③
  AND  (c.listed_from IS NULL OR :year >= c.listed_from) -- 3.1 ④
ORDER BY cy.revenue DESC, c.stock_code ASC;              -- 3.3
```

**선택 기업 보장**: 위 쿼리는 선택 기업도 같은 조건으로 걸러지므로, `is_selected` 행이
결과에 없으면 3.2의 예외(해당 연도 데이터 없음)에 해당한다. 애플리케이션은 이걸 확인해
비교 화면 대신 "해당 연도 데이터 없음"을 표시한다.

`max_peers` 를 쓰게 되면 (B 확장 시) 마지막에 다음을 덧붙인다.

```sql
-- 선택 기업은 상한에서 제외한 뒤 나머지에만 LIMIT 을 건다
LIMIT (:max_peers + 1)
```

정확히는 선택 기업이 상한 밖으로 밀려날 수 있으므로, **선택 기업 1행을 UNION 으로 따로
붙이는 방식**이 안전하다. A 범위에서는 필요 없어 지금 구현하지 않는다.

## 7. 확장 시 바뀌는 것 (D-1을 B로 뒤집을 경우)

규칙 자체는 그대로 쓸 수 있게 썼다. 바뀌는 건 두 가지뿐이다.

| | A (현재) | B |
|---|---|---|
| 모집단 | `targets.csv` 10개사 | 같은 `ksic_division` 상장사 전체 |
| `max_peers` | `NULL` (무제한) | 값 필요. 선택 기업은 상한 밖에서 보장 |

그 외 그룹 기준·정렬·동률·결측 처리는 동일하다. **단 B는 해당 기업들의 지표 수집이
선행되어야 한다** — 업종당 수백 콜. 규칙 문제가 아니라 수집 범위(WP-5) 문제다.

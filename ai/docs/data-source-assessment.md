- 상태: 조사 중
- 조사 기준일: 2026-09-09
- 대상 기능: 기업 맥락 연결, 직무 연결 분석
- 관련 결정: [[Decisions/ai/rag-mvp-feature-contracts]]
- 데이터 저장 결정: [[Decisions/ai/evaluation-evidence-storage]]

## 1. 문서 목적

1차 MVP의 기능 계약에 필요한 데이터와 현재 프로젝트가 실제로 재현할 수 있는 데이터를
비교한다. 출처가 있다는 사실과 수집·저장·갱신 가능한 데이터셋이 있다는 사실을 구분한다.

## 2. 판단 기준

| 기준 | 확인 내용 |
| --- | --- |
| 기능 적합성 | 기능 계약의 주장·요구사항을 판정할 원문이 있는가 |
| 출처 신뢰도 | 발행 주체와 원문 출처를 확인할 수 있는가 |

| 최신성 | 기준일, 게시일, 마감일과 갱신 주기를 관리할 수 있는가 |
| 재현 가능성 | 다른 팀원이 동일한 입력을 다시 만들 수 있는가 |

| 품질 검증 | 누락, 중복, 잘못된 기업 연결을 탐지할 수 있는가 |

`확보`는 저장소와 파이프라인에서 다른 팀원이 재현할 수 있는 상태를 뜻한다. 개인 로컬
캐시나 Git에 포함되지 않은 산출물만 있는 경우에는 완전히 확보한 것으로 보지 않는다.

### 3.1 제공 파일 직접 확인 결과

| 파일 | 직접 확인한 내용 | 남은 확인 |
| --- | --- | --- |
| `dart_local.zip` | 2.78GB, 전체 항목 16,228개, XML 12,334개, 압축 해제 기준 약 27.9GB | 전체 기업·연도·보고서별 분포 |
| `ssafy_dataset_news_2024.csv` | 3,835,467,733바이트, 1,704,684건, 2024-01-01~2024-12-31 | 이용 조건과 기사별 기업 매핑 정답 |
| `ssafy_dataset_news_2025.csv` | 3,270,566,604바이트, 1,323,543건, 2025-01-01~2025-12-31 | 이용 조건과 기사별 기업 매핑 정답 |

XML은 파일별 인코딩 차이를 전제로 처리해야 한다. 앞서 확인한 표본 중에는 XML 선언과 실제
디코딩 결과가 맞지 않는 파일이 있었고, 삼성전자 2024년 사업보고서는 UTF-8로 정상 복원됐다.
파서는 UTF-8 엄격 디코딩을 먼저 시도하고 실패하면 CP949를 시도한다. ZIP을 전부 압축
해제하면 약 27.9GB가 필요하므로 기준선에서는 대상 기업·연도의 파일만 ZIP에서 읽는다.

뉴스 CSV는 기사 본문의 줄바꿈과 따옴표를 포함하므로 물리적인 줄 수를 기사 수로 사용할 수
없다. 위 건수는 `|` 구분자와 CSV 인용 규칙을 적용한 스트리밍 파서로 계산했다. 두 파일에서
CSV 컬럼 수가 깨진 행은 발견되지 않았다. 삼성전자 정확 표기는 2024년 제목 5,770건·본문
27,506건, 2025년 제목 4,041건·본문 26,084건에서 확인됐다. 본문 등장은 다른 기업 기사의
단순 언급일 수 있으므로 파일럿 후보는 제목에 `삼성전자`가 정확히 등장한 기사로 제한한다.

따라서 현재 범용성이 있는 구조화 근거는 기업 마스터, 업종 마스터, 재무 지표 5종이다.
사업부 지표와 기업 활동은 일부 기업을 대상으로 한 실험용 데이터로 취급한다.

### 3.3 삼성전자 파일럿 확인 결과

- `company.csv`에서 삼성전자 `corp_code=00126380`을 확인했다.
- 2021~2025년 재무 지표 5종이 연도별로 모두 존재한다.
- 사업부 지표는 24행이며 사업부 직원 수는 있지만 사업부 매출은 결측이다.
- 기업 활동은 2021~2025년 `corporate_invest` 700행이며 금액 결측은 53행이다.
- 2024년 사업보고서 접수번호 `20250311001085`의 XML이 ZIP에 존재하고 기업 코드도
  `00126380`으로 일치한다.
- 회사·사업 개요, 주요 제품, 매출, 연구개발, 기타 참고사항에서 21개 텍스트 후보를
  추출했다.
- 제목 기업명 정확 일치와 사업 관련성 규칙으로 뉴스 후보 30건을 추출했다.

파일럿은 기준일을 `2025-12-31`로 고정했다. 이 날짜에 공개되지 않았던 2025 사업연도
보고서는 사용하지 않고, 2025년 3월 11일 제출된 2024 사업연도 보고서를 사용한다.

사용자가 제공한 약 10GB의 원본은 현재 로컬 다운로드 경로에서 읽었고 저장소 안으로
복사하지 않았다. 원본 관리의 목표 위치는 사업보고서가 `data/raw/opendart/filings`, SSAFY
뉴스가 `data/raw/ssafy_news`다. 팀 공용 저장 위치와 뉴스 이용 조건을 정하기 전에는 중복
복사하지 않고 CLI 입력 경로와 source profile의 파일명·SHA-256으로 원본을 식별한다.

## 4. 기능별 데이터 요구사항과 공백

### 4.1 기업 맥락 연결

| 필요한 데이터 | 현재 사용할 수 있는 것 | 공백 |
| --- | --- | --- |
| 기업 식별자 | DART `corp_code`와 기업 마스터 | 없음 |
| 매출·영업이익·당기순이익·자본·부채 | 정식 `company_metric` 시드 | 수치 중심 주장만 검증 가능 |
| 직원·평균급여·평균근속·R&D 비율 | 10개사 스냅샷 | 대상 기업 제한, 정식 적재 경로 확인 필요 |
| 사업·제품·전략·연구개발 원문 | 사용자가 보유한 사업보고서 원본 | 파일 구조·범위 확인과 `company_text` 변환 필요 |
| 최근 기업 활동 원문 | SSAFY 뉴스 데이터셋의 `article` 필드 | 전체 범위, 대상 기업 매핑과 이용 조건 미확정 |

현재 정식 시드만으로는 재무 수치 중심의 주장만 안정적으로 확인할 수 있다. 직원·R&D
지표는 10개사 스냅샷의 사용 위치와 정식 적재 경로를 추가로 확인해야 한다. 제품, 사업
전략과 최근 기술 동향까지 평가하려면 사업보고서 본문 또는 뉴스 원문 근거가 필요하다.

### 4.2 사업보고서와 뉴스의 메타데이터

메타데이터는 사업보고서와 뉴스 모두에 필요하다. 공통 필드와 출처별 필드를 나눠 관리한다.

#### 공통 필드

| 필드 | 필요한 이유 |
| --- | --- |
| `document_id` | 같은 문서를 다시 식별하고 중복을 제거하기 위해 필요 |
| `source_type` | DART와 뉴스를 구분해 출처 우선순위를 적용하기 위해 필요 |
| `target_corp_code` | 다른 기업의 문서가 검색 결과에 섞이는 것을 막기 위해 필요 |
| `title` | 사용자에게 출처를 설명하고 사람이 원문을 확인하기 위해 필요 |
| `published_at` 또는 `reference_period` | 과거 정보를 현재 사실처럼 사용하는 것을 막기 위해 필요 |
| `source_locator` | URL, DART 접수번호 또는 원본 파일 위치로 근거를 다시 찾기 위해 필요 |
| `content` | 실제 판정과 인용에 사용할 원문 |
| `content_hash` | 같은 원문 중복과 변경 여부를 확인하기 위해 필요 |
| `ingested_at` | 어떤 시점의 데이터로 실험했는지 재현하기 위해 필요 |

#### DART 사업보고서 전용 필드

- `corp_code`
- `rcept_no`
- `report_name`
- `fiscal_year`
- `filed_at`
- `section_name`
- 원문 내 페이지, 문단 또는 문자 위치

#### 뉴스 전용 필드

- `publisher`
- `reporter`
- `category`
- `original_url`
- `published_at`

첨부된 SSAFY 뉴스 예시는 `company`, `title`, `link`, `published`, `category`,
`category_str`, `reporter`, `article` 필드를 가진다. 예시에서 `company` 값이 `여성신문`이고
기사 대상은 `한샘`이므로, 이 필드는 대상 기업보다 언론사를 뜻하는 것으로 보인다. 데이터
사전으로 의미를 확인하기 전까지 `company`를 `target_corp_code`로 사용하지 않는다.

예시 필드는 다음처럼 우선 매핑할 수 있다.

| 원본 필드 | 내부 필드 | 상태 |
| --- | --- | --- |
| `company` | `publisher` | 샘플 기반 추정, 데이터 사전 확인 필요 |
| `title` | `title` | 사용 가능 |
| `link` | `original_url` | 사용 가능 |
| `published` | `published_at` | 형식 파싱 필요 |
| `category`, `category_str` | `category` | 검색 필터 사용 여부 검토 |
| `reporter` | `reporter` | 선택 메타데이터 |
| `article` | `content` | 기업 주장 판정의 원문 후보 |

SSAFY 뉴스 데이터에는 대상 기업 식별자가 보이지 않으므로 기사 본문에서 기업을 찾고 DART
`corp_code`에 연결하는 별도 매핑이 필요하다.

### 4.3 직무 연결 분석

| 필요한 데이터 | 현재 사용할 수 있는 것 | 공백 |
| --- | --- | --- |
| 대상 기업·직무의 실제 공고 원문 | 없음 | 전체 |
| 공고 식별자와 출처 | 없음 | 전체 |
| 게시일·마감일·유효 상태 | 없음 | 전체 |
| 공고의 업무·필수·우대 요구사항 | 없음 | 전체 |

따라서 기준선에서는 사용자 또는 평가자가 실제 공고 원문 한 개를 직접 제공해야 한다.
자동 검색을 제공하려면 별도의 수집·저장·갱신 경로가 필요하다.

## 5. 기준선에서 사용할 임시 데이터 방식

| 기능 | 기준선 입력 방식 |
| --- | --- |
| 기업 맥락 연결 | 평가자가 검증한 DART·뉴스 근거를 사례에 고정 |
| 직무 연결 분석 | 사용자 또는 평가자가 실제 채용 공고 원문 한 개를 제공 |
| 사용자 경험 | 자소서 초안에 작성된 내용만 사용 |

이 방식은 분석 기능을 빠르게 평가하기 위한 것이며 자동 수집과 검색 가능성을 증명하지
않는다.

### 5.1 삼성전자 고정 근거 묶음

삼성전자 파일럿용으로 17건을 선택했다.

| 출처 | 건수 | 포함 범위 |
| --- | ---: | --- |
| DART 구조화 재무 지표 | 5 | 2024년 매출·영업이익·당기순이익·자본·부채 |
| DART 사업보고서 | 6 | 사업 구조·제품·연구개발·특허·모바일·반도체 전략 |
| SSAFY 뉴스 | 6 | 기술 협력·HBM·AI 가전·차량용 반도체·전장 인수·AI 제품 방향 |

선택 규칙은
`ai/company_context/data/configs/samsung-electronics-selection.json`에 기록한다.
자동 추출 후보는 `data/staged`, 선택된 평가 근거는 `data/curated/evaluation`, 본문을 제외한
계보 정보는 `data/manifests/evaluation`에 둔다. 기사 본문과 사업보고서 추출문은 Git에
커밋하지 않는다. 뉴스 이용 조건이 확정되지 않았으므로 이 묶음은 로컬 평가 입력으로만
사용한다.

## 6. 우선 조사 항목

1. 삼성전자 고정 근거로 기업 맥락 연결 평가 사례 10개 이상을 작성한다.
2. SSAFY 뉴스 데이터의 저장·AI 입력·결과 노출 조건을 확인한다.
3. 전체 사업보고서의 인코딩 분포와 기업·연도별 커버리지를 확인한다.
4. 채용 공고를 어떤 출처에서 지속적으로 확보할 수 있는가.
5. 채용 공고 원문 저장, 사용자 제공 원문 임시 처리와 삭제 정책은 무엇인가.
6. 기업·직무·게시일·마감일을 어떤 식별자와 스키마로 관리할 것인가.

## 7. 단계 완료 조건

- 각 필수 데이터가 `사용 가능`, `제한적으로 사용`, `사용 불가` 중 하나로 판정된다.
- 사용할 출처마다 수집·저장·갱신·AI 입력 가능 여부가 기록된다.
- 기준선용 입력과 실제 서비스용 자동 데이터 경로가 구분된다.
- 확보할 수 없는 데이터가 있으면 기능 범위 또는 사용자 필수 입력이 수정된다.

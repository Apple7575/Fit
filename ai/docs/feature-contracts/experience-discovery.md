# 기능 계약: 대화를 통한 경험 발굴

- 상태: 후속 단계 초안
- 목적: 사용자의 경험에서 가장 중요한 누락 정보를 찾아 대화로 보완한다.

1차 MVP에서는 기업 맥락 연결과 직무 연결 분석을 우선한다. 이 계약은 두 기능의 기준선과
평가 방법을 검증한 뒤 다시 검토한다.

## 1. 사용자 상황과 호출 조건

다음 상황에서 호출한다.

- 사용자가 특정 경험을 정리하거나 구체화해 달라고 요청했다.
- 자소서 또는 경험 분석에서 중요한 정보의 누락이 발견됐다.
- 다른 역할이 판단을 계속하려면 사용자 확인이 필요하다.

## 2. 입력

| 구분 | 내용 |
| --- | --- |
| 필수 | 사용자가 해결하려는 질문 또는 목표 |
| 필수 | 대화, 이력서, 프로젝트 설명 또는 자소서에서 확인되는 경험 정보 하나 이상 |
| 필수 | 현재 대화 상태와 지금까지 확인된 사용자 사실 |
| 선택 | 자소서 문항과 초안 |
| 선택 | 직무 연결 분석 결과 |
| 선택 | 글자 수 제한 |

## 3. 서비스 판단

경험을 다음 기준으로 분석하고 사용자 목표에 가장 중요한 누락 정보 하나를 선택한다.

- 상황과 해결할 문제
- 사용자의 목표와 맡은 역할
- 사용자가 직접 수행한 행동
- 방법을 선택한 이유와 판단 과정
- 팀 성과와 구분되는 사용자 기여
- 결과와 결과를 확인한 방법

## 4. 판단 근거

사용자가 대화에서 직접 확인한 사실을 가장 우선한다. 그다음 이력서와 프로젝트 설명,
자소서 원문 순으로 사용한다.

- 외부 기업 문서는 사용자 경험의 사실 근거로 사용하지 않는다.
- 직무 연결 분석은 질문 우선순위에만 사용한다.
- 모델의 추론은 사용자 사실로 저장하지 않는다.

## 5. 결과와 상호작용

사용자에게 현재 확인된 경험, 가장 중요한 누락 정보, 후속 질문 하나와 질문 이유를
제공한다.

- 한 번에 한 가지 질문만 한다.
- 사용자가 답을 모르면 추정값을 요구하지 않고 미확인 상태로 둔다.
- 수치가 없다면 측정 방법, 관찰 결과 또는 정성적 근거가 있는지 확인한다.
- 사용자가 이전 내용을 수정하면 가장 최근의 명시적 답변을 우선한다.
- 핵심 정보가 충분하거나 사용자가 중단을 요청하면 질문을 끝낸다.

## 6. 성공 조건

- 이미 확인된 내용을 반복해서 묻지 않는다.
- 질문이 사용자 요청, 자소서 문항 또는 직무 연결에 직접 필요하다.
- 추가된 모든 사실을 사용자 발화나 제출 문서로 추적할 수 있다.
- 대화 후 사용자의 행동과 기여가 이전보다 구체적으로 구조화된다.
- 사용자가 답하지 못한 정보는 미확인으로 남는다.

## 7. 실패 조건

- 이미 제공된 정보를 다시 질문한다.
- 여러 질문에 동시에 답하도록 요구한다.
- 특정 성과나 수치가 있었음을 전제로 유도 질문을 한다.
- 모델이 추론한 내용을 사용자 사실로 기록한다.
- 종료 조건 없이 질문을 반복한다.

## 8. 판단하지 않는 것

- 경험의 진실 여부
- 사용자의 역량 수준 또는 합격 가능성
- 사용자가 제공하지 않은 정확한 성과 수치
- 기업 내부 평가자가 해당 경험에 부여할 점수

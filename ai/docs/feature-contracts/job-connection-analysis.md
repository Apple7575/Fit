# 기능 계약: 직무 연결 분석

- 상태: 확정
- 우선순위: 1차 MVP
- 목적: 채용 자료에 명시된 직무 요구사항과 자소서에 작성된 사용자 경험이 실제로
  연결되는지 근거 단위로 확인한다.
- 관련 결정: [[Decisions/ai/rag-mvp-feature-contracts]]

## 1. 기준선 범위

기준선은 대상 기업 한 개, 대상 직무 한 개, 자소서 문항 한 개와 초안 한 개를 분석한다.
단일 에이전트가 평가용으로 고정한 실제 채용 공고를 입력받아 판단하며,
검색 기술과 멀티에이전트 구조는 포함하지 않는다.

기준선은 자소서에 작성된 내용만 사용자 경험의 근거로 사용한다. 이력서와 대화를 함께
분석하는 기능은 후속 범위다.

## 2. 사용자 상황과 호출 조건

다음 상황에서 호출한다.

- 사용자가 자소서의 경험이 지원 직무와 관련 있는지 확인하려 한다.
- 채용 공고의 어떤 요구사항을 자소서가 뒷받침하는지 확인하려 한다.
- 기술명이나 직무 키워드를 언급했지만 실제 행동으로 역량을 보여줬는지 확인하려 한다.

직무 근거 자료가 없으면 일반적인 직무 지식으로 요구사항을 만들어내지 않고 분석할 수
없다고 반환한다.

## 3. 입력

| 구분 | 내용 |
| --- | --- |
| 필수 | 대상 기업의 식별 가능한 이름 |
| 필수 | 대상 직무의 식별 가능한 이름 |
| 필수 | 자소서 문항 한 개 |
| 필수 | 자소서 초안 한 개 |
| 필수 | 대상 기업·직무의 실제 채용 공고 원문 한 개 |
| 선택 | 공고 제목, 공고 ID, 게시일, 마감일과 URL 등의 메타데이터 |

현재 프로젝트에는 채용 공고 데이터셋과 자동 수집 경로가 없다. 따라서 기준선에서는
사용자 또는 평가자가 실제 공고 원문 한 개를 직접 제공해야 한다. 서비스가 공고를 자동으로
수집·검색하는 기능은 데이터 확보 가능성을 검증한 뒤 별도로 설계한다.

## 4. 서비스가 수행할 판단

### 4.1 직무 요구사항 추출

채용 자료에 명시된 요구사항을 독립적으로 평가할 수 있는 의미 단위로 추출한다.

| 유형 | 내용 |
| --- | --- |
| `RESPONSIBILITY` | 입사 후 수행할 업무와 책임 |
| `REQUIRED_SKILL` | 필수 기술과 지식 |
| `PREFERRED_SKILL` | 우대 기술과 경험 |
| `QUALIFICATION` | 경력, 학력, 자격 등 지원 조건 |
| `WORK_COMPETENCY` | 협업, 문제 해결 등 공고에 명시된 업무 역량 |

공고에 없는 역량을 해당 직무의 보편적인 필수 역량으로 추가하지 않는다. 여러 요구사항이
한 문장에 섞여 있다면 원문의 의미를 훼손하지 않는 범위에서 분리한다.

### 4.2 사용자 경험 근거 추출

자소서에서 다음 내용을 사용자 경험 근거로 추출한다.

- 사용자가 수행한 행동과 담당 역할
- 행동에 사용한 기술과 지식
- 행동을 선택한 이유와 해결하려던 문제
- 결과와 사용자가 기여한 범위

팀 전체의 결과를 사용자의 개인 행동이나 성과로 확대 해석하지 않는다. 자소서에 없는
이력과 경험은 `없음`이 아니라 `자소서에서 확인할 수 없음`으로 처리한다.

### 4.3 요구사항과 경험 연결 판단

각 직무 요구사항과 자소서 경험 사이의 연결을 다음 중 하나로 판정한다.

| 판정 | 기준 |
| --- | --- |
| `DIRECT` | 구체적인 행동이나 결과가 요구사항을 직접 보여줌 |
| `PARTIAL` | 관련 경험은 있지만 역할, 행동, 수준 또는 결과의 설명이 부족함 |
| `KEYWORD_ONLY` | 관련 기술명이나 역량 표현만 있고 이를 보여주는 경험 근거가 없음 |
| `NO_EVIDENCE` | 자소서에서 연결할 내용을 확인할 수 없음 |
| `NOT_ASSESSABLE` | 채용 자료의 표현이 모호해 연결 기준을 정할 수 없음 |

`DIRECT`는 해당 요구사항과의 연결이 자소서에 드러난다는 의미이며 숙련도, 합격 가능성이나
다른 지원자 대비 경쟁력을 의미하지 않는다.

### 4.4 연결 이유 설명

연결 판정에는 반드시 다음 두 원문을 함께 제시한다.

- 판단 대상이 된 채용 자료의 요구사항 문장
- 연결 대상으로 사용한 자소서 경험 문장

판정 이유는 두 문장 사이에서 일치하는 행동, 기술, 대상과 결과를 설명한다. 단어가
일치한다는 사실만으로 경험이 요구사항을 증명한다고 판단하지 않는다.

## 5. 판단 근거와 데이터 범위

1차 기준선은 대상 기업과 직무가 일치하는 실제 채용 공고 한 개만 직무 요구사항의 근거로
사용한다.

DART와 뉴스는 기업 맥락 분석 자료이므로 직무의 필수·우대 역량을 정의하는 근거로
사용하지 않는다. 기업의 공식 직무 설명, 다른 기업의 유사 직무 공고와 일반적인 직무
지식도 현재 확보하지 않았거나 범위가 넓어질 수 있으므로 기준선에서 제외한다.

자료의 기업, 직무, 게시일과 유효기간을 확인할 수 없으면 해당 근거의 상태를
`사용 불가`로 표시한다. 과거 공고는 현재 공고인 것처럼 사용하지 않고 평가 사례의 기준일과
일치할 때만 사용한다.

## 6. 사용자에게 주는 결과

### 6.1 요구사항별 결과

```json
{
  "requirement_id": "job-requirement-001",
  "requirement": "채용 자료에서 추출한 요구사항",
  "requirement_type": "REQUIRED_SKILL",
  "source_evidence": {
    "quote": "채용 자료의 원문 문장",
    "title": "공고 제목",
    "publisher": "기업명",
    "published_at": "YYYY-MM-DD",
    "expires_at": "YYYY-MM-DD",
    "url": "https://example.com"
  },
  "connection_verdict": "PARTIAL",
  "essay_evidence": ["연결 판단에 사용한 자소서 문장"],
  "reason": "요구사항과 경험 사이의 연결 또는 부족한 근거",
  "missing_information": ["본인의 구체적인 행동", "기여한 범위"]
}
```

### 6.2 전체 요약

- 채용 자료에서 추출한 요구사항 수와 유형
- 자소서에서 직접 연결된 요구사항
- 설명이 부족하거나 키워드만 언급된 요구사항
- 자소서에서 확인할 수 없는 요구사항
- 가장 먼저 보완할 연결과 필요한 정보
- 분석에 사용한 채용 자료와 기준일

기준선은 사용자가 모든 요구사항을 자소서 하나에 포함해야 한다고 권고하지 않는다.
문항의 목적과 글자 수를 고려한 경험 선택과 수정은 후속 기능에서 다룬다.

## 7. 성공 조건

- 모든 직무 요구사항을 채용 자료의 원문과 대응하도록 추출한다.
- 모든 연결 판정에 요구사항 근거와 자소서 근거를 함께 제시한다.
- 기술 키워드의 언급과 실제 경험 증거를 구분한다.
- 자소서에서 확인되지 않는 경험을 추측하지 않고 `NO_EVIDENCE`로 표시한다.
- 사용자가 어떤 경험의 어떤 설명을 보완해야 하는지 알 수 있다.

정확도와 최소 통과 수치는 평가셋을 만든 뒤 확정한다.

## 8. 실패 조건

- 공고에 없는 기술이나 역량을 필수 요구사항으로 생성한다.
- 다른 기업이나 다른 직무의 공고를 근거로 사용한다.
- 기술 키워드가 있다는 이유만으로 직무 경험이 충분하다고 판정한다.
- 팀 성과를 사용자의 개인 행동이나 성과로 확대한다.
- 자소서에 없는 경험을 있다고 추정한다.
- 요구사항 연결 정도를 지원자의 전체 직무 적합성이나 합격 가능성으로 표현한다.
- 분석 범위를 넘어 새로운 경험이나 완성된 자소서를 작성한다.

## 9. 판단하지 않는 것

- 실제 합격 가능성과 채용 결과
- 기업 내부의 평가 기준과 요구 수준
- 공고에 명시되지 않은 숨은 역량
- 다른 지원자보다 직무에 더 적합한지 여부
- 자소서에 작성되지 않은 사용자의 경험과 숙련도

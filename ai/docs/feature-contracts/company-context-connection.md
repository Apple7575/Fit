# 기능 계약: 기업 맥락 연결

- 상태: 확정
- 우선순위: 1차 MVP
- 목적: 자소서에 사용된 기업 관련 주장과 지원 이유가 공개된 기업 근거에 의해
  뒷받침되는지 확인한다.
- 관련 결정: [[Decisions/ai/rag-mvp-feature-contracts]], [[Decisions/ai/company-context-connection-rubric]]

## 1. 기준선 범위

기준선은 대상 기업 한 개, 대상 직무 한 개, 자소서 문항 한 개와 초안 한 개를 분석한다.
단일 에이전트가 평가용으로 고정한 기업 근거를 입력받아 판단하며, 검색 기술과
멀티에이전트 구조는 포함하지 않는다.

## 2. 사용자 상황과 호출 조건

다음 상황에서 호출한다.

- 사용자가 자소서에 작성한 기업 정보가 사실인지 확인하려 한다.
- 기업 정보가 지원 이유를 실제로 뒷받침하는지 확인하려 한다.
- 자소서가 어느 기업에도 적용할 수 있는 일반적인 지원동기인지 확인하려 한다.

자소서에 기업 관련 주장이나 지원 이유가 없다면 내용을 만들어내지 않고 분석할 대상이
없다고 반환한다.

## 3. 입력

| 구분 | 내용 |
| --- | --- |
| 필수 | 대상 기업의 식별 가능한 이름 |
| 필수 | 현재 지원 세션의 대상 직무 |
| 필수 | 자소서 문항 한 개 |
| 필수 | 자소서 초안 한 개 |
| 실행 전제 | 대상 기업에 관한 평가용 근거 문서 한 개 이상 |
| 선택 | 문서 제목, 출처, 작성일, 기준일과 URL 등의 메타데이터 |

근거 문서는 사용자가 반드시 준비해야 하는 입력이 아니다. 서비스가 확보한 자료를
기준선 실행 전에 제공한다. 근거 문서가 없으면 사실 확인과 연결 판단을 수행하지 않고
`NOT_VERIFIABLE`로 반환한다.

## 4. 서비스가 수행할 판단

### 4.1 기업 관련 주장 추출

자소서에서 외부 자료로 확인할 수 있는 기업 관련 주장을 문장 또는 의미 단위로 추출한다.

- 사업, 제품, 서비스와 시장에 관한 사실
- 기술, 연구개발과 투자 방향에 관한 사실
- 공식적으로 발표된 전략, 목표와 성과
- 위 정보를 근거로 사용자가 제시한 지원 이유

사용자의 가치관, 희망과 경험 자체는 기업 사실 주장으로 분류하지 않는다.

### 4.2 기업 사실 검증

각 주장과 근거 문서가 같은 기업, 사업, 시점과 대상을 가리키는지 확인한 뒤 다음 중 하나로
판정한다.

| 판정 | 기준 |
| --- | --- |
| `SUPPORTED` | 근거가 주장의 핵심 내용을 직접 뒷받침함 |
| `PARTIALLY_SUPPORTED` | 일부는 확인되지만 범위, 시점 또는 표현이 과장됨 |
| `CONTRADICTED` | 신뢰할 수 있는 근거가 주장과 명시적으로 충돌함 |
| `NOT_VERIFIABLE` | 제공된 자료만으로 확인하거나 반박할 수 없음 |

단순히 비슷한 단어가 등장하는 것만으로 `SUPPORTED`라고 판정하지 않는다.

### 4.3 지원 이유 연결 판단

기업 정보가 사용자의 경험, 관심 또는 지원 목적과 어떤 논리로 연결되는지 확인한다.

| 판정 | 기준 |
| --- | --- |
| `DIRECT` | 기업의 구체적 특성과 사용자의 경험 또는 목표 사이의 이유가 설명됨 |
| `INDIRECT` | 관련 요소는 있으나 중간 설명이 빠져 연결을 추론해야 함 |
| `DISCONNECTED` | 기업 정보와 사용자 이야기가 함께 있지만 인과 관계가 제시되지 않음 |
| `NOT_APPLICABLE` | 지원 이유나 연결을 판단할 내용이 없음 |
| `NOT_ASSESSABLE` | 기업 사실을 확인할 수 없어 근거 기반 연결 판단을 보류함 |

판정 단위는 해당 기업 주장과 자소서 전체에 나온 사용자의 경험 또는 입사 후 목표 사이의
관계다. `DIRECT`는 동일 기술·제품·사업 영역이 등장하는 것만으로는 부족하며, 그 기업 특성이
사용자의 경험 또는 목표로 이어지는 이유가 자소서에 명시돼야 한다. 주제만 비슷하면
`INDIRECT`, 양쪽 내용은 있지만 관계가 없으면 `DISCONNECTED`로 판정한다.

사실 판정이 `NOT_VERIFIABLE`이면 연결 판정은 `NOT_ASSESSABLE`로 두고 연결 품질 지표에서
제외한다. 사실 오류와 연결 부족을 한 점수에서 중복 처벌하지 않기 위한 규칙이다.

이 판정은 지원동기의 합격 가능성이나 기업 내부 평가 점수를 의미하지 않는다.

## 5. 판단 근거

1차 기준선은 현재 확보한 다음 자료만 판단 근거로 사용한다.

1. DART 공시와 사업보고서
2. 현재 보유한 뉴스 데이터 중 발행 주체와 작성일을 확인할 수 있는 기사

DART 자료를 우선 사용하고 DART에서 확인하기 어려운 최근 사업, 제품, 기술과 시장 동향은
뉴스 데이터로 보완한다. 기업 공식 홈페이지·채용 페이지·뉴스룸과 다른 공공기관 자료는
현재 확보하지 않았으므로 기준선 근거에서 제외한다.

각 판정에는 원문 근거 문장과 출처를 연결한다. DART와 뉴스가 충돌하면 발행 주체,
기준일과 원문 맥락을 비교하고 충돌 사실을 결과에 표시한다.

## 6. 사용자에게 주는 결과

### 6.1 주장별 결과

```json
{
  "claim_id": "company-claim-001",
  "claim": "자소서에서 추출한 기업 관련 주장",
  "claim_type": "BUSINESS_OR_PRODUCT",
  "fact_verdict": "PARTIALLY_SUPPORTED",
  "connection_verdict": "INDIRECT",
  "essay_evidence": "주장이 포함된 자소서 문장",
  "source_evidence": [
    {
      "quote": "판정에 사용한 근거 문장",
      "title": "문서 제목",
      "publisher": "발행 주체",
      "published_at": "YYYY-MM-DD",
      "url": "https://example.com"
    }
  ],
  "reason": "판정 이유",
  "missing_link": "사용자 경험과 기업 정보 사이에서 빠진 설명"
}
```

`claim_type`은 기준선에서 다음 값만 사용한다.

- `BUSINESS_OR_PRODUCT`
- `TECHNOLOGY_OR_RND`
- `STRATEGY_OR_GOAL`
- `PERFORMANCE`
- `OTHER`

### 6.2 전체 요약

- 확인된 주장과 확인되지 않은 주장 수
- 가장 먼저 고쳐야 할 사실 오류 또는 과장
- 지원 이유가 기업 특성과 직접 연결된 부분
- 연결을 위해 추가로 설명해야 할 부분
- 분석에 사용한 근거 목록과 기준일

기준선은 수정된 자소서 전문을 작성하지 않는다. 사실 오류가 있거나 연결이 부족한 위치와
그 이유까지만 제시한다.

## 7. 성공 조건

- 자소서의 기업 관련 주장을 원문과 대응하도록 추출한다.
- 각 사실 판정에 같은 기업과 적절한 시점의 근거를 제시한다.
- 사실 검증과 지원 이유 연결 판단을 서로 구분한다.
- 근거가 없는 주장은 추측하지 않고 `NOT_VERIFIABLE`로 표시한다.
- 사용자가 어떤 문장을 왜 보완해야 하는지 알 수 있다.

정확도와 최소 통과 수치는 평가셋을 만든 뒤 확정한다.

## 8. 실패 조건

- 자소서에 없는 기업 관련 주장이나 지원 이유를 생성한다.
- 다른 기업, 다른 사업 또는 맞지 않는 시점의 자료를 근거로 사용한다.
- 근거 문장이 없는 상태에서 사실이라고 단정한다.
- 사실이 맞다는 이유만으로 좋은 지원동기라고 평가한다.
- 출처 간 충돌을 숨기고 하나의 사실로 단정한다.
- 분석 범위를 넘어 새로운 경험이나 완성된 자소서를 작성한다.

## 9. 판단하지 않는 것

- 실제 합격 가능성
- 기업 내부의 평가 기준과 선호
- 공개되지 않은 사업 계획과 조직 문화
- 다른 지원자보다 기업에 더 적합한지 여부
- 사용자가 제공하지 않은 경험과 지원 이유

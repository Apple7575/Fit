# 자소서 피드백 멀티에이전트 RAG 설계

- 상태: 초안
- 현재 단계: 6. 가장 단순한 기준선 구현 완료 및 결과 검토
- 작성일: 2026-09-08
- 작업 브랜치: `docs/rag-design`

## 목표

사용자가 작성한 자소서 한 개를 대상으로 기업 관련 주장과 사용자 경험이 기업·직무
근거에 적절히 연결됐는지 확인하도록 돕는다.

RAG와 멀티에이전트 구조를 먼저 결정하지 않는다. 사용자 가치와 기능 계약을 정한 뒤
동일한 평가셋에서 기준선과 개선안을 비교하고, 측정 결과로 검색 및 에이전트 구조를
선택한다.

## 현재 상태

| 단계 | 상태 | 완료 또는 다음 조건 |
| --- | --- | --- |
| 1. 문제와 사용자 가치 정의 | 완료 | 문제 가설 4개와 1차·후속 우선순위 확정 |
| 2. 가치별 기능 계약 정의 | 완료 | 기업 맥락 연결·직무 연결 분석 계약 확정 |
| 3. 성공 지표와 목표 정의 | 완료 | 품질·안전·운영·검색 지표와 초기 통과 기준 확정 |
| 4. 데이터 요구사항과 확보 가능성 조사 | 진행 중 | 삼성전자 기업 근거 파일럿 확보, 뉴스 이용 조건과 채용 공고 조사 필요 |
| 5. 평가 데이터셋 구축 | 부분 완료 | 가상 자소서 1개·기업 주장 10개 정답 초안 작성, 2차 검토 필요 |
| 6. 가장 단순한 기준선 구현 | 완료 | Qwen3-32B-AWQ 단일 호출과 JSON 검증·CSV/Markdown 평가 산출 구현 |
| 7. 실패 분석과 개선 가설 수립 | 완료 | 오답 4건을 근거 절단·표 오독·범위 누락·주장 정규화 오류로 분류 |
| 8. RAG 개선 실험 | 진행 중 | BM25 첫 후보는 고정 근거 대비 품질 하락, 검색 누락 개선 필요 |
| 9. 역할과 에이전트 구조 실험 | 대기 | 안정된 검색 기준선에서 단일·다중 구조 비교 |
| 10. 기술 아키텍처 확정 | 대기 | 실험 결과로 구성 요소 선택 |
| 11. 서비스 통합과 운영 검증 | 대기 | 아키텍처 확정 후 진행 |

## 전체 흐름

```text
문제와 가치 정의
→ 가치별 기능 계약
→ 성공 지표와 사전 안전 기준 정의
→ 데이터 요구사항과 확보 가능성 조사
→ 평가 데이터셋과 검색 정답지 구축
→ 단순 기준선 구현
→ 실패 사례 분석과 개선 가설 수립
→ RAG 개선 실험
→ 단일·다중 에이전트 비교
→ 결과 기반 기술 아키텍처 확정
→ 서비스 통합과 운영 검증
→ 운영 지표를 통한 반복 개선
```

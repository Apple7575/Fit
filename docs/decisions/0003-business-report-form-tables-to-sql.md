# 0003. 사업보고서 서식 표는 SQL 행 테이블로 옮기고, 벡터 검색은 서술 문단만 대상으로 한다

- 상태: 제안
- 작성자: WinterI5Coming (초안은 Claude 가 작성, 근거 수치는 로컬 DB 집계로 검증)
- 날짜: 2026-09-19
- 관련 이슈: (미정)

## 배경

기업 분석 담당의 숫자 오류는 지금까지 전부 사업보고서 **표**에서 났다. 우리금융지주 은행 부문 이익을 지주사 전체로 쓴 것, 우리자산운용 22,133백만원을 지주사 이익으로 쓴 것, 덕산테코피아 수출·내수를 뒤바꾼 것, 채팅의 단위·연도·정의 오류가 모두 표 안의 숫자를 모델이 읽어 옮기는 과정에서 생겼다. 서술 문단에서 숫자가 틀린 사례는 발견되지 않았다.

100개사 청크 DB(`ca_rag_adaptive_rowspan_v2`)를 집계하면 사업보고서 청크 631,068건 중 표가 548,902건(87%)이고 서술은 82,166건(13%)이다. 표는 재무제표 주석 116,229건, 임원 현황·계열회사·타법인출자·이사회 같은 DART 정형 서식이 100개사 모두에 있다. 이 표들이 지금은 서술 문단과 같은 자격으로 BM25·벡터 색인에 들어가고 모델 입력으로 넘어간다.

채팅의 표준 지표(매출액·영업이익 등)는 이미 `company_metric` 확정값으로 결정적으로 답하도록 바꿔 10개사 56문항에서 오답 0을 확인했다. 같은 원리를 표 전체에 적용하려면 표를 숫자로 저장해야 한다.

## 결정

DART 서식이 정해진 표를 골라 **행 단위 SQL 테이블**로 옮긴다. 답에 들어가는 숫자는 이 테이블과 `company_metric`에서만 가져오고, 모델은 문장만 쓴다. 벡터·BM25 색인은 서술 문단만 대상으로 하되, 표 캡션에 붙은 서술문은 서술로 남긴다. 기존 표 청크와 근거 ID는 그대로 두어 인용 계보와 소속 법인 테이블(`rag_evidence_entity_scope`)을 재사용한다.

1단계 대상 서식과 집계(100개사, 첫 조각 기준):

| 서식 | 표 수 | 기업 수 | 머리글 예 |
| --- | --- | --- | --- |
| 직원 현황 | 421 | 100 | 구분 · 인원수 · 연간급여 총액 · 1인평균 급여액 |
| 임원 현황 | 2,402 | 100 | 성명 · 성별 · 출생년월 · 직위 · 담당업무 · 주요경력 |
| 계열회사 현황 | 1,781 | 100 | 상장여부 · 회사수 · 기업명 · 법인등록번호 |
| 타법인출자 현황 | 4,199 | 100 | 법인명 · 출자목적 · 기초잔액 · 기말잔액 · 지분율 |
| 매출실적 | 283 | 57 | 사업부문 · 매출유형 · 품목 · 수출/내수 · 기수별 금액 |
| 주요 제품 매출 | 625 | 70 | 매출유형 · 품목 · 연도별 금액 · 비율 |
| 수주상황 | 211 | 31 | 품목 · 수주일자 · 납기 · 수주총액 · 수주잔고 |
| 연구개발비 | 646 | 68 | 과목 · 연도별 금액 · 연구개발비/매출액 비율 |
| 영업부문 실적 | 228 | 77 | 사업부문 · 회사명 · 구분 · 기수별 금액 |

저장 형태는 하나의 긴 테이블 `company_table_row` 다. 열은 `corp_code`, `rcept_no`, `form_code`, `evidence_id`(원 표 청크), `row_no`, `entity_scope`, `row_labels`(행 이름 경로, 예 `전기변환 기기류부문 > 제품매출 > 수배전반류 > 수출`), `column_key`(머리글 경로, 예 `제51기`), `fiscal_year`, `value_num`, `value_text`, `unit`, `parse_status`. 서식별로 열 이름을 정규화한 뷰를 그 위에 둔다. 값이 숫자로 읽히지 않으면 `value_text` 에 원문을 두고 `parse_status=TEXT` 로 남겨 버리지 않는다.

파서는 기존 `data/pipeline/business_report/doc.py` 의 `Table`(행렬 `m`, `header_rows`, 캡션, 단위, 소속 법인)을 입력으로 쓰는 별도 모듈로 만들고, 청킹·임베딩 코드는 건드리지 않는다. 적재는 `rag_evidence_entity_scope` 백필과 같은 방식(기업별 UPSERT, 병렬)으로 한다.

## 대안과 근거

- **프롬프트와 검증 규칙을 더 강화한다.** 9월 16~18일에 단위 검사, 소속 법인 검사, 시장 통계 검사, 부문 범위 게이트를 차례로 붙였지만 매번 새 유형의 표 오류가 나왔다. 표를 읽는 단계가 남아 있는 한 규칙은 뒤따라갈 뿐이다. 탈락.
- **모든 표를 정형화한다.** 재무제표 주석 116,229건과 정정신고 등은 형식이 기업마다 달라 파서를 일반화할 수 없다. 취준생 질문에 쓰이는 서식 9종부터 하고, 나머지 표는 지금처럼 검증기로 거르며 모델 입력에서 우선순위를 낮춘다.
- **표를 벡터 색인에서 완전히 뺀다.** 캡션에 서술문이 붙은 표(예 "가. 주요사업의 내용 …")는 검색 정답이 되는 경우가 골드 문항 검토에서 5건 있었다. 캡션 서술은 서술 청크로 남기고 행 데이터만 뺀다.
- **정형 저장을 JSON 한 열로 한다.** 조회는 쉽지만 연도·단위·소속 법인으로 걸러 모델에 값만 넘기는 용도에는 긴 테이블이 맞고, 기존 `company_metric` 도 같은 구조다.

## 결과

1단계 적재 완료(2026-09-19, 실험 기록 시도 21): V33 `company_table_row` 에 100개사 서식 표 2,354개·398,829행을 넣었다. 리포트·채팅이 이 값을 쓰는 변경과 정식 사람 검수는 아직이다. 표본 검토에서 확인한 위험과 대응:

- **열 밀림의 원인은 TU 셀 누락이다.** 임원 현황 표본(`00162461`)에서 `성별`·`출생년월` 자리에 `직위`·`담당업무` 값이 들어가 있었다. 시험 파서 dry run(실험 기록 시도 20)으로 원인을 찾았다. DART XML 은 날짜·구분 값을 `<TU>` 셀에 담는데 `data/config/patterns.yaml` 의 `cell_tags: [TD, TE, TH]` 가 이를 읽지 않아 칸이 빠진다. 5개사 최신 보고서 표 12,101개 중 337개(2.8%)가 해당하고 임원·주식·타법인출자·계열회사 서식에 몰려 있다. `cell_tags` 에 TU 를 추가해야 하며, 이는 해당 표 청크의 내용·해시가 바뀌는 재청킹 대상이라 청킹 담당(사용자)이 시점을 정한다. 서식 파서는 그와 별개로 열 수·숫자 열·자료형 패턴 검사를 두고, 어긋나면 `parse_status=MISALIGNED` 로 표시해 숫자 답에 쓰지 않는다.
- **머리글 2행.** 수주상황·타법인출자 표는 머리글이 두 줄(`수주총액 | 수주총액` 위에 `수량 | 금액`)이고 현재 청크는 둘째 줄을 데이터 행처럼 담고 있다. `header_rows` 가 있는 THEAD 를 기준으로 머리글 경로를 만들고, THEAD 가 없으면 첫 행이 전부 문자인지로 판정한다.
- **단위 줄.** 표 내용 첫 줄이 `(단위 : 백만원)` 만인 경우가 많다. 머리글 추출 시 단위 전용 줄은 건너뛰고 단위 메타에 합친다. 직원 현황·미등기임원 보수처럼 단위 메타가 비어 있으면 서식 기본 단위(백만원, 5개사 실측으로 확인)를 쓰고 단위 출처를 남긴다.
- **기수 표기.** `제51기`, `2023년(제39기)`, `제22기(2025년)` 이 섞여 있다. 접수번호의 사업연도로 기수를 연도로 환산하고 환산 근거를 `column_key` 원문과 함께 남긴다.

성공 기준: 5개사(나노솔루션·덕산테코피아·디에이피·삼성전자·우리금융지주)에서 서식 9종의 행을 원문과 사람이 대조해 값·단위·소속 법인 오류 0건, 열 밀림 표는 전부 `MISALIGNED` 로 잡힘. 그 뒤 리포트 서술과 채팅이 이 테이블의 값을 쓰도록 바꾸고, 골드 53문항 검색 지표와 5개사 보고서 의미 검사를 전후 비교한다.

후속 과제: 부문별 실적처럼 서식이 자유로운 표의 정형화 범위, 2,700개사 확장 시 행 수(100개사 기준 수십만 행 예상)와 인덱스, 청크 DB 임베딩 저장을 pgvector 로 옮기는 별도 결정.

집계 SQL과 표본 추출, 이 문서 초안은 Claude 가 작성했다. 표 비율·서식별 건수는 로컬 DB 조회 결과를 그대로 옮겼고, 열 밀림·머리글 2행·단위 줄 문제는 표본 청크 원문에서 직접 확인했다. 대상 서식 선정과 성공 기준은 사람이 확정해야 한다.

# 전체 에이전트 입력 방어 설계

## 목표

모든 에이전트가 같은 정책으로 사용자 메시지와 외부 자료를 검사하고, 취업 준비와 무관하거나 위험하거나 규칙을 우회하려는 입력을 에이전트 호출 전에 차단한다. 판정이 애매하면 실행하지 않고 다시 표현해 달라고 요청한다.

이 설계는 완전한 프롬프트 인젝션 방지를 주장하지 않는다. 입력 정규화, 결정적 규칙, 제한된 의미 판정, 문맥 격리, 출력 검사, 속도 제한, 적대적 회귀 테스트를 겹쳐 우회 가능성과 피해 범위를 줄인다.

## 성공 기준

- 채용공고·경험·기업분석·글쓰기·뉴스·총괄 등 모든 채팅 에이전트가 같은 판정 결과와 고정 응답을 사용한다.
- 명백한 무관 질문, 위험 요청, 프롬프트 인젝션은 AI를 호출하지 않는다.
- 판정이 애매하거나 난독화된 요청은 `NEED_REPHRASE`로 종료한다.
- 차단된 메시지는 감사 목적으로 저장하되 이후 LLM 대화 문맥에는 포함하지 않는다.
- 자소서, 채용공고, OCR, URL, RAG 자료에 포함된 지시는 데이터로만 취급하며 의심스러운 자료는 격리한다.
- 모델 출력이 내부 규칙, 민감정보, 허용되지 않은 형식 또는 범위 밖 내용을 포함하면 사용자에게 전달하지 않는다.
- 공통 적대적 테스트 코퍼스로 Java 입구와 Python 실행 계층의 정책 불일치를 검출한다.

## 비목표

- 모든 가능한 자연어 공격을 100% 탐지한다고 보장하지 않는다.
- 별도 보안 모델을 학습하거나 외부 보안 제품을 도입하지 않는다.
- 일반 목적 대화 기능을 제공하지 않는다. 이 서비스는 취업 준비 도메인으로 제한한다.
- 이번 작업에서 관리자용 보안 대시보드를 만들지 않는다.

## 위협 모델

### 직접 사용자 입력

- 이전 지시 무시, 역할 변경, DAN·개발자 모드, 시스템 프롬프트 추출
- 번역·요약·인용·코드블록·JSON 변환으로 포장한 규칙 추출
- 여러 턴에 나눈 공격, 과거 차단 문장의 복호화·완성 요구
- Base64·hex·ROT13·역순·제로폭 문자·유사 문자·과도한 공백을 이용한 난독화
- 불법 행위, 폭력, 개인정보 탈취, 문서 위조, 공격적·차별적 출력 요구
- 잡담, 음식 추천, 코딩 과제, 정치·의료·법률 상담 등 취업 준비 범위 밖 요청
- 매우 긴 입력, 반복 입력, 동시 요청을 이용한 비용 소진

### 간접 입력

- 자소서, 채용공고, OCR 이미지, URL 본문에 포함된 지시
- 뉴스, 사업보고서, RAG 청크에 삽입된 지시
- 차단됐지만 대화 기록에 남은 과거 사용자 메시지
- 다른 에이전트의 출력에 포함된 도구 실행·규칙 변경 지시

### 출력

- 시스템 프롬프트, 내부 정책, API 키, 연결 문자열, 내부 식별자 노출
- 범위 밖 답변, 유해 콘텐츠, 허용하지 않은 URL·Markdown·HTML
- 스키마를 벗어난 출력 또는 근거 없는 도구 실행 결과

## 공통 판정 모델

모든 입력은 다음 중 하나로 판정한다.

| 결정 | 의미 | 처리 |
|---|---|---|
| `ALLOW` | 취업 준비 관련 정상 요청 | 에이전트 호출 |
| `REFUSE_SCOPE` | 명백한 범위 밖 요청 | 고정 범위 안내로 즉시 종료 |
| `REFUSE_SAFETY` | 위험·불법·개인정보·자해 관련 요청 | 종류별 고정 안전 안내로 즉시 종료 |
| `REFUSE_INJECTION` | 규칙 우회·역할 변경·내부 정보 추출 | 고정 거절로 즉시 종료 |
| `NEED_REPHRASE` | 난독화됐거나 의도가 불명확함 | 평문으로 다시 표현해 달라고 안내 |
| `QUARANTINE_SOURCE` | 외부 자료에 실행 지시가 포함됨 | 자료 처리를 중단하고 원인을 안내 |

엄격 모드를 사용한다. 결정적 규칙이나 의미 판정이 확실한 `ALLOW`를 내리지 못하면 에이전트를 호출하지 않는다. 단순 키워드 포함만으로 정상 경험을 막지 않도록 문장 전체 의도와 자료 출처를 함께 본다.

## 처리 흐름

### 1. 정규화

`PolicyTextNormalizer`가 원문을 보존하면서 검사본을 만든다.

- Unicode NFKC 적용
- 제로폭 문자, 제어 문자, bidi 제어 문자 탐지 및 제거
- 공백·문장부호 분산 축약
- 과도한 반복과 비정상 문자 비율 계산
- 인코딩·복호화 지시와 긴 인코딩 블록 표시
- 길이 상한 적용

원문과 정규화한 검사본을 모두 규칙에 대입한다. 정규화 과정에서 의미 손실 위험이 있으면 `NEED_REPHRASE`로 판정한다.

### 2. 결정적 규칙

Java 백엔드의 공통 `InputGuard`를 정책 게이트로 확장한다. 모든 사용자 채팅은 `TurnService`에서 방과 에이전트 종류에 상관없이 같은 게이트를 지난다.

규칙은 다음 우선순위를 사용한다.

1. 자해 위기 안내
2. 위험·불법·개인정보 침해
3. 프롬프트 인젝션과 내부 정보 추출
4. 난독화·비정상 입력
5. 명백한 범위 밖 요청
6. 취업 준비 관련 허용 신호
7. 나머지는 제한된 의미 판정

### 3. 제한된 의미 판정

정규식만으로 확정할 수 없는 요청은 별도의 정책 판정 경로로 보낸다. 판정기는 도구, 대화 기록, 자소서, 공고, 비밀값에 접근하지 않으며 정규화된 현재 문장만 받아 고정 enum JSON을 반환한다.

- 허용 출력은 `ALLOW`, `REFUSE_SCOPE`, `REFUSE_SAFETY`, `REFUSE_INJECTION`, `NEED_REPHRASE`뿐이다.
- JSON 파싱 실패, 타임아웃, 제공자 오류는 `NEED_REPHRASE`로 닫는다.
- 판정기 응답은 사용자에게 직접 노출하지 않는다.
- 명백한 결정적 규칙은 판정기를 호출하지 않는다.

### 4. 외부 자료 격리

자소서와 공고처럼 사용자가 직접 작성한 자료, OCR·URL·RAG처럼 외부에서 온 자료는 `UntrustedContentGuard`를 거친다.

- 자료 내부의 명령형 문장을 사용자 지시로 승격하지 않는다.
- 규칙 변경, 비밀 추출, 도구 실행, 점수 강요 지시를 탐지하면 `QUARANTINE_SOURCE`로 처리한다.
- 의심 구간을 조용히 삭제한 뒤 계속 처리하지 않는다. 사용자가 원본을 수정하거나 다른 자료를 제출하도록 안내한다.
- 프롬프트에는 신뢰된 애플리케이션 지시와 비신뢰 자료를 구조적으로 분리한다.

### 5. 대화 문맥 격리

`agent_message`에 다음 정책 메타데이터를 저장한다.

- `policy_action`: 공통 판정 값
- `policy_reason`: 안정적인 사유 코드
- `context_eligible`: 이후 LLM 문맥 포함 여부
- `policy_version`: 판정 규칙 버전

거절·재표현 요청·격리 판정을 받은 사용자 메시지와 그 고정 응답은 화면에는 보이되 `context_eligible=false`로 저장한다. 대화 문맥 조회는 이 값을 기준으로 제외한다. 문자열 비교로 거절 응답을 식별하지 않는다.

### 6. 에이전트 권한 제한

- 에이전트별 도구 허용 목록은 코드로 고정한다.
- 사용자나 외부 자료가 도구 이름, 인자, 실행 순서를 지시할 수 없다.
- 모델이 생성한 내부 식별자를 그대로 신뢰하지 않는다.
- 데이터 조회는 현재 사용자·방·기업 범위를 서버 코드에서 검증한다.

### 7. 출력 검사

`OutputGuard`가 사용자에게 전달하기 전 결과를 검사한다.

- 시스템·개발자 지시와 내부 정책 노출 패턴
- 비밀값과 연결 문자열 형태
- 허용하지 않은 Markdown·HTML·외부 URL
- 응답 스키마 위반
- 범위 밖 또는 명백히 유해한 내용

검사 실패 시 원문 출력을 폐기하고 고정 오류 응답을 저장한다. 실패 출력은 전체 본문 대신 사유 코드와 해시만 로그에 남긴다.

### 8. 남용 제한과 복구

- 사용자·방 단위 속도 제한과 동시 턴 제한
- 동일 차단 지문 반복 시 짧은 cooldown
- 입력 길이와 모델 출력 토큰 상한
- 일정 시간 이상 남은 `PENDING`·`RUNNING` 턴 자동 실패 처리
- 로컬 개발 환경의 높은 한도와 운영 한도를 분리

## 데이터와 인터페이스

Java 공통 판정 인터페이스는 다음 의미를 제공한다.

```java
PolicyDecision evaluate(PolicyInput input);

record PolicyInput(String rawText, InputSource source) {}
record PolicyDecision(PolicyAction action, String reason, String reply, String policyVersion) {}
```

`InputSource`는 최소 `CHAT`, `COVER_LETTER`, `JOB_POSTING`, `OCR`, `URL`, `RAG`, `AGENT_OUTPUT`을 구분한다. 사용자에게 보여줄 문구는 사유 코드와 분리해 한곳에서 관리한다.

## 테스트 전략

`security/adversarial-input-cases.json`을 Java와 Python 테스트가 함께 읽는다. 각 사례는 원문, 출처, 기대 판정, 설명을 가진다.

필수 분류:

- 정상 취업 질문과 키워드 충돌 사례
- 직접·간접 프롬프트 인젝션
- 한국어·영어·혼합 언어
- 공백·유니코드·인코딩 난독화
- 여러 턴 공격과 차단 메시지 재주입
- 개인정보·불법·폭력·자해
- 범위 밖 잡담과 욕설
- 문서·OCR·URL·RAG 공격
- 출력 유출과 스키마 위반
- 길이·반복·동시성 남용

테스트는 최소 다음을 증명해야 한다.

- 차단된 요청에서 `TurnExecutor`와 AI 클라이언트가 호출되지 않는다.
- 모든 단일 담당 방과 총괄 방이 같은 판정을 사용한다.
- 차단된 메시지가 다음 정상 턴의 대화 기록에 포함되지 않는다.
- 정상적인 식당 아르바이트·고객 욕설 대응 경험 질문은 허용된다.
- 정책 판정기 장애 시 에이전트가 호출되지 않는다.
- 출력 검사 실패 시 원문이 사용자에게 저장되지 않는다.

## 단계적 적용

1. 공통 테스트 코퍼스와 입력 정규화·결정적 정책 게이트
2. 정책 메타데이터 저장과 대화 문맥 격리
3. 외부 자료 격리
4. 제한된 의미 판정
5. 출력 검사
6. 반복 공격 제한, 오래된 턴 복구, 운영 지표

각 단계는 독립적으로 테스트하고 배포 가능해야 한다. 첫 단계만으로도 현재 글쓰기 담당의 점심 추천 회귀는 막아야 한다.

## 운영 기준

- 정책 버전별 허용·차단·재표현 건수를 기록한다.
- 원문 전체를 보안 로그에 남기지 않는다.
- 정상 질문 오탐과 공격 미탐을 별도로 측정한다.
- 새로운 우회 사례는 공통 코퍼스에 먼저 추가한 뒤 규칙을 수정한다.
- 운영 중 차단율 급증, 정상 질문 오탐 신고, 새로운 문서 입력 경로 추가 시 설계를 재검토한다.

## 근거

- OWASP LLM01:2025 Prompt Injection은 입력·출력 필터, 외부 자료 분리, 최소 권한, 적대적 테스트를 함께 적용하도록 권고한다.
- OWASP LLM07:2025 System Prompt Leakage는 시스템 프롬프트를 보안 통제로 신뢰하지 말고 모델 외부의 결정적 통제를 사용하도록 권고한다.
- NIST AI 600-1은 프롬프트 인젝션, 데이터 오염, 모델 추출, 자원 소진 입력에 대한 반복적인 레드팀 테스트와 측정을 권고한다.

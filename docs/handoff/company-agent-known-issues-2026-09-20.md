# 기업 분석 담당 — 로컬 검증에서 드러난 문제 (2026-09-20)

`feat/agent-chat-api` 에서 담당 방 연결(무상태 대화 API + 자동 리포트)을 로컬 스택으로 끝까지
돌려 본 기록이다. 연결 자체는 동작한다. 아래는 이번 작업 범위 밖이라 고치지 않고 남긴 것들이다.

검증 방법: `infra/local.sh` 로 스택 기동 → 자소서("현대자동차") 저장 → `POST /api/rooms/defaults`
→ 기업 RAG 담당 방(자동 검토)에서 리포트 확인 → 이어서 질문 1회.

---

## 1. 리포트 말풍선에 근거가 0건이다

**증상**: 자동 검토로 뜬 리포트 말풍선의 `evidences` 가 비어 있다. 이어지는 대화 답변에는
근거가 2건 붙는다(`COMPANY_METRIC`).

**원인 추정**: `CompanyAnalysisClient.report()` 는 리포트의 `sources[]` 를 근거로 옮기는데,
`stage` 가 `DETERMINISTIC` 인 리포트에는 `sources[]` 가 아직 비어 있는 것으로 보인다. 사업보고서
출처는 서술 단계에서 붙는 듯하다 — `ai/company_analysis/service.py` 의
`build_deterministic_report` 와 `_enrich` 가 `sources` 를 각각 어떻게 채우는지 확인이 필요하다.

**영향**: 낮음. 리포트 본문 끝의 "### 출처" 도 같이 비므로 화면이 어긋나 보이지는 않는다.
서술이 붙은 뒤 다시 열면 채워지는지 아직 확인하지 않았다.

---

## 2. "주요 제품" 에 제품명이 아니라 표 머리글이 들어간다

**증상**: 현대자동차 리포트에서

```
**주요 제품**
- 금액, 차량부문, 내부매출액, 기타부문
```

"금액", "내부매출액" 은 표의 열·행 이름이지 제품이 아니다. 같은 값이 경쟁사 비교 표의
`주요 제품` 칸에도 그대로 들어간다.

```
| 회사명 | 주요 제품 | 매출(조원) | ... |
| 현대자동차 | 금액, 차량부문, 내부매출액 | 186.3 | ... |
```

비교 대상인 기아("승용, RV, 상용")·현대모비스("제49기, 샤시, 칵핏모듈")를 보면 회사마다
품질이 다르다 — 현대모비스의 "제49기" 도 기수 표기가 섞여 들어간 것이다.

**원인 추정**: 사업보고서의 제품 표에서 제품명 열을 고르는 규칙이 표 서식에 따라 빗나간다.
정형 표(`company_table_row`)가 아니라 청크에서 뽑는 경로일 가능성이 있다.

**영향**: 중간. 리포트 첫 화면과 경쟁사 표에 모두 보이는 값이라 눈에 띈다. 숫자가 아니라
이름이라 확정 지표 검증기가 걸러 내지 못한다.

**참고**: 이번 작업 이전부터 있던 문제다. 리포트 생성 로직(`ai/company_analysis/facts.py` ·
`table_facts.py`) 쪽이고, 담당 방 연결과는 무관하다.

---

## 3. 자동 검토 직후 리포트에는 서술·SWOT 이 없다

**증상**: 검토 방에 처음 들어가면 `stage` 가 `DETERMINISTIC` 이라 숫자 블록만 보인다.
사업 서술·SWOT·출처가 빠진다. 3~4분 뒤 백그라운드 서술이 끝나면 채워진다.

**현재 처리**: `CompanyAnalysisClient` 가 말풍선 끝에 안내를 붙인다 — "아직 이 기업의 서술
분석을 만드는 중입니다. 잠시 뒤 다시 물어보면 더 자세히 답할 수 있습니다."

**설계상 정상 동작이지만**, 사용자가 처음 보는 화면이 반쪽이다. 해소하려면 리포트를 미리
만들어 둬야 한다(`POST /company/internal/reports`, 기업당 약 200초). 2,640개사를 전부 미리
만드는 것은 현실적이지 않으므로, 자소서에 자주 등장하는 기업부터 돌리는 식의 선별이 필요하다.

**한 가지 더**: 말풍선은 만들어질 때 한 번 저장되고 끝이다. 서술이 나중에 붙어도 이미 뜬
말풍선은 그대로다. 사용자가 다시 물어야 최신 리포트를 본다.

## 배포 전 확인 사항 (이번에 로컬에서 먼저 걸렸다)

백엔드가 기동에 실패했다.

```
Migration to version "30 - company analysis report" failed!
Caused by: relation "company_analysis_report" already exists
```

로컬 DB 에 파이썬 쪽이 테이블을 직접 만들어 둬서 Flyway 와 부딪혔다. `company_analysis_report`
· `company_analysis_conversation` · `company_analysis_message` 를 지우고 재기동하니 V27~V33 이
전부 적용됐다.

**배포 DB 에도 같은 확인이 필요하다.** 손으로 만든 테이블이 남아 있으면 배포가 그 자리에서
멈춘다. 확인은 `select version, success from flyway_schema_history where version::numeric >= 27`.

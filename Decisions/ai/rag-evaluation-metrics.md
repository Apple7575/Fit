# RAG 기준선 평가 지표와 초기 통과 기준

## 문제

기업 맥락 연결과 직무 연결 분석의 최소 기준선이 성공했는지 판단할 평가 단위, 지표와
최소 통과 기준이 필요했다.

## 검토한 선택지

1. 전체 응답에 대한 사람의 주관적 점수만 사용한다.
2. 정확도 하나로 추출과 판정 품질을 함께 평가한다.
3. 추출·판정·근거·안전·운영 지표를 분리하고 파일럿과 본 평가를 구분한다.
4. 검색 지표를 고정 근거 기준선부터 적용한다.

## 트레이드오프

- 주관적 점수는 빠르지만 실패 원인을 설명하거나 실험 후보를 비교하기 어렵다.
- 정확도 하나는 계산이 쉽지만 누락과 클래스 불균형을 가릴 수 있다.
- 지표를 분리하면 라벨링 비용이 늘지만 검색, 추출, 판정 중 어디서 실패했는지 확인할 수
  있다.
- 고정 근거 기준선에는 검색 과정이 없으므로 검색 지표를 적용해도 의미가 없다.

## 결정

- 기업 주장과 직무 요구사항 추출은 Precision·Recall·F1으로 평가한다.
- 범주형 판정은 클래스별 F1의 평균인 Macro F1으로 평가한다.
- 판정에 사용한 원문이 실제 판정을 뒷받침하는지 근거 적합률로 평가한다.
- 사용자 경험 생성, 근거 생성과 대상 기업·직무 혼입은 허용하지 않으며 최소 기준을 0건으로
  둔다.
- 구조화 출력 성공률의 최소 기준은 100%로 둔다.
- 대표 사례 10개 이상의 파일럿에서는 안전과 출력 형식을 우선 확인한다.
- 품질 최소 기준은 [[ai/docs/evaluation-experiment-plan]] 2.5의 초기 기준을 적용한다.
- Recall@5와 Precision@5 등의 검색 지표는 RAG를 추가한 실험부터 사용한다.
- 응답시간, 토큰과 비용은 실행 환경이 정해지기 전까지 통과 기준 없이 비교값만 기록한다.

## 이유

품질을 하나의 점수로 압축하지 않고 실패 위치를 추적해야 이후 RAG와 에이전트 구조 변경의
효과를 설명할 수 있다. 안전 오류는 평균 점수로 상쇄하면 안 되므로 별도의 실패 조건으로
분리한다.

## 재검토 조건

- 정답 라벨 검토자 사이의 불일치가 반복되어 현재 판정 기준을 안정적으로 적용할 수 없는 경우
- 본 평가셋의 판정값 분포가 초기 최소 기준을 평가하기에 부족한 경우
- 첫 기준선 결과에서 지표가 실제 사용자 품질과 다른 방향으로 움직이는 경우
- RAG 검색 또는 멀티에이전트 평가 단계로 넘어가 새 지표가 필요한 경우

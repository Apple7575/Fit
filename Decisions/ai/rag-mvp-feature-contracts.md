# RAG 1차 MVP 기능 계약과 데이터 전제

## 문제

기업 맥락 연결과 직무 연결 분석을 1차 MVP로 구현하려면 각 판단이 사용할 근거와 현재
보유하지 않은 직무 데이터를 어떻게 처리할지 결정해야 했다.

## 검토한 선택지

1. 현재 보유한 DART와 뉴스만으로 기업·직무 분석을 모두 수행한다.
2. 서비스가 채용 공고를 자동 수집한다고 가정하고 직무 분석을 설계한다.
3. 기업 분석은 보유 자료를 사용하고, 직무 분석 기준선은 실제 채용 공고를 직접 입력한다.
4. 일반적인 직무 지식이나 다른 기업의 유사 공고로 대상 직무 요구사항을 추정한다.

## 트레이드오프

- DART와 뉴스만 사용하면 바로 시작할 수 있지만 대상 채용 건의 요구 역량을 신뢰성 있게
  정의할 수 없다.
- 자동 수집을 전제로 하면 사용자 입력을 줄일 수 있지만 현재 데이터셋과 수집 경로가 없어
  구현 가능성을 보장할 수 없다.
- 실제 공고를 직접 입력하면 기준선을 빠르게 만들 수 있지만 사용자가 준비해야 할 자료가
  늘고 자동화된 서비스 범위는 검증하지 못한다.
- 일반 직무 지식과 유사 공고는 자료를 구하기 쉽지만 대상 기업·채용 건에 없는 역량을
  필수라고 판단할 위험이 있다.

## 결정

- 1차 MVP의 핵심 가치는 기업 맥락 연결과 직무 연결 분석으로 확정한다.
- 하나의 기준선 실행은 기업 한 개, 직무 한 개, 자소서 문항 한 개와 초안 한 개를 다룬다.
- 기업 맥락 연결은 현재 보유한 DART 공시·사업보고서와 뉴스만 근거로 사용한다.
- 직무 연결 분석은 대상 기업·직무의 실제 채용 공고 원문 한 개만 근거로 사용한다.
- 채용 공고 데이터셋과 자동 수집 경로를 확보하기 전까지 사용자 또는 평가자가 공고 원문을
  직접 제공한다.
- 단일 에이전트와 고정 근거를 사용하는 최소 기준선을 먼저 평가한다.
- DART, 뉴스, 일반적인 직무 지식과 다른 기업의 유사 공고로 직무 요구사항을 생성하지 않는다.

## 이유

현재 보유 데이터와 기능 약속을 일치시키고, 근거 없는 직무 역량 생성을 막기 위해서다.
고정 근거를 사용하는 단일 에이전트부터 시작하면 검색 실패와 분석 실패를 분리해 측정할 수
있으며 기준선을 빠르게 구현할 수 있다.

## 재검토 조건

- 채용 공고를 지속적으로 수집·저장·갱신할 수 있는 경로를 확보한 경우
- 기준선 평가에서 현재 판정값이나 출력 구조가 실패 원인을 구분하지 못하는 경우
- MVP가 이력서, 여러 자소서 문항 또는 여러 기업·직무를 함께 다루도록 확장되는 경우

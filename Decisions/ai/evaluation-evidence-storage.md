# AI 평가 외부 근거의 저장 위치

## 문제

기업 맥락 연결 기준선에서 생성한 DART·뉴스 후보와 선택된 근거, 평가 정답을 모두
`ai/` 또는 `data/staged/` 한곳에 둘지, 데이터 단계와 책임에 따라 분리할지 결정해야 했다.

## 검토한 선택지

1. 원본부터 평가 결과까지 모두 `ai/` 아래에 둔다.
2. 후보와 선택된 근거를 모두 `data/staged/`에 둔다.
3. 외부 근거는 `data/`의 단계별 경로에 두고 AI가 소유하는 평가 사례만 `ai/`에 둔다.

## 트레이드오프

- `ai/`에 모으면 실험 파일을 찾기 쉽지만 기존 데이터 정본과 관리 규칙이 분리되고 외부
  본문이 복제된다.
- `data/staged/`에 모으면 단순하지만 자동 생성 후보와 사람이 선택한 평가 입력을 구분할 수
  없다.
- 단계별로 분리하면 경로가 늘어나지만 원본·후보·선택 근거·평가 정답의 책임과 Git 정책을
  각각 적용할 수 있다.

## 결정

- DART·뉴스 원본은 `data/raw`에 둔다.
- 자동 추출 후보는 `data/staged`에 둔다.
- 사람이 선택한 외부 평가 근거는 `data/curated/evaluation`에 둔다.
- 본문 없는 출처·건수·해시·선택 계보는 `data/manifests/evaluation`에 둔다.
- 평가 자소서, 기대 판정, 금지 결과와 루브릭은 `ai/evals`에 둔다.
- 뉴스와 사업보고서 본문은 이용 조건이 확정될 때까지 Git에서 제외한다.

## 이유

데이터의 위치를 소비 주체보다 데이터의 성격과 가공 단계로 결정해야 기존 `raw`·`staged`·
`curated` 기준을 유지할 수 있다. 외부 근거와 AI 평가 정답을 분리하면 데이터 이용 조건과
평가 버전을 독립적으로 관리할 수 있다.

## 재검토 조건

- SSAFY 뉴스 데이터의 저장·외부 AI 입력·결과 노출 조건이 확정돼 Git 추적 정책을 바꿀 때
- AI 모듈이 별도 저장소나 별도 배포 단위로 분리돼 데이터 정본의 소유권이 바뀔 때
- 평가 근거가 파일이 아니라 전용 데이터베이스나 객체 저장소로 관리될 때
